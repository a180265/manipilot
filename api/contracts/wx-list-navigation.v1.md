# 微信主页列表导航契约 v1

首次定义：2026-09-12（外部插件 1.6.0）；2026-09-14 的兼容加固对应 1.6.1。
当前源码清单为 [`wx-wechat-adapter` 1.7.1](../../examples/plugins/wx-wechat-adapter/manifest.json)，
旧任务契约仍并存；源码版本不证明实际安装、启用或手势已登记。

## 任务与边界

`POST /v1/tasks` 提交 `wx_list_navigate`，`contract_version` 固定为
`wx-list-navigation.v1`。任务完整格式见同名 JSON Schema。
WX 只发送档案编号与版本、轮次编号、动作和步号，不发送手势坐标、
客户名单、回复内容或点击目标。通用任务清单通过 `context_fields`
保存账号上下文；平台不内置微信导航调度。

| 字段 | 中文语义 |
| --- | --- |
| navigation_id | 导航轮次编号；与原任务一起用于人工复核关联 |
| navigation_profile | 已登记导航档案引用，只有 profile_id 和 version |
| action=next | 按档案查找方向滑动一次，然后交由 WX 识别新画面 |
| action=top | 有限回顶，必须由档案的顶部锚点和区域确认 |
| step_index | 正整数步号；next 不得超过档案 max_swipes |

执行前必须无持有聊天、设备账号绑定一致、档案有效且微信主页已确认。
next 保存前后截图并核对连续增加的摄像头帧编号和相同尺寸；
滑动后再次确认主页。不点击任何联系人，不创建执行会话，不输入或发送。
top 复用既有有限回顶逻辑，未启用回顶或锚点不明确不报告成功。
机械臂、摄像头及绑定异常按原门禁处理；所有动作仍受租约、权限与动作预算限制。

2026-09-14 兼容加固（插件源码 1.6.1，任务格式不变）：
回顶需等待画面稳定，再在第二张新帧中确认顶部专属文字仍位于登记区域，
位置差不超过 2 个相机像素，并保存确认截图。动画经过、旧帧或取证失败保持未知，
不继续滑动。成功详情保留 `top_verified: true`，增加可选
`top_confirmation`，记录 `kind: stable_top_anchor`、首末帧编号及证据编号。
真机滑动必须有 `motion_verified: true`，显式 `swipe_executed: false` 不能成功；
仅有指令接收回包不足以继续读取下一页并点击。
WX 核对原任务的导航轮次、动作及前后证据；缺少匹配步骤证据时不能
把任务的 `confirmed` 单独当作回顶成功。此加固不放宽设备或校准门禁。

WX 读取 `gesture-profile.v1` 时新增无坐标元数据：
`navigation_limits: {"max_swipes": 10, "return_to_top": true}`。
这里是档案声明，不表示设备在线或真机手势已验收。

## 失败与人工恢复

动作结果未知、帧未更新、画面不匹配均停止，不重试旧滑动。
WX 查询原任务终态，不得把相同动作换新任务编号重放。
人工确认手机已回到微信主页后，可通过既有任务核对接口传入：

```json
{
  "expected_navigation_id": "原导航轮次编号",
  "observed_ui_state": "wechat_main"
}
```

插件只在编号与任务匹配、设备一致、无持有聊天时返回
`context_released=true`。平台仍核对原任务终态和设备执行占用。
人工核对不会重做动作、改写旧结果、解除设备暂停或恢复校准资格。
WX 后续创建新的回顶检查，不续跑原未知 next。

## 手机手动返回同步

新增 `wx_session_release`，沿用 `wx-session.v1`，
payload 与 `wx_session_exit` 相同。它核对旧执行会话、账号、外部聊天
和 daemon 会话，采集新证据确认微信主页，再释放旧执行上下文。
不会点击返回、停靠、输入或移动。清除前再次核对会话和主页。
若用户仍在聊天里或旧执行上下文已改变，则保留原状态。

此任务在清单声明 `read_only_task: true`。平台拒绝其动作计划与任何
机械臂/输入写能力；收尾只读检查连接、位置和摄像头质量，不调用
归位或停止。它仍取得短时独占租约，不能与其他任务同时整理执行状态。
旧任务缺少该声明时保持原有生命周期。
