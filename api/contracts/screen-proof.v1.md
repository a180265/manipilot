# 登记区域视觉证据

日期：2026-09-11。能力版本：`camera.observe_regions 1.0.0`。

## 边界

Arm Fleet 保存设备级视觉档案，提供区域 OCR、页面特征、色块和新鲜帧证据；
平台不判断客户、允许名单、销售事实，也不解释是否发出微信消息。
`wx-wechat-adapter 1.5.0` 解释证据，WX 保持业务授权与身份事实源。

档案：`data/devices/{device_id}/screen_proof.json`。独立于校准及固定目标。
绑定设备、摄像头、物理摄像头、绑定版本、daemon 会话、分辨率、屏幕几何及
相机变换；任一改变必须重新登记。服务重启但绑定不变时自动加载。
文件原子替换，带递增版本及操作人审计；内容含受控区域截图，不进入通用日志。

### 共享布局来源（v1 兼容扩展）

设备存在已选共享适配时，页面识别、标题识别、`camera.observe_regions`、
`camera.locate_text` 和下面的
只读元数据接口优先使用该适配及其精确模板/粗框版本。没有已选适配才使用旧档案；
指针未完成迁移、已选版本损坏、摘要不符、绑定/几何变化或资料不完整均拒绝，
不得悄悄回退旧档案。模板发布本身不授予动作资格，不修改 `ui_targets`。
固定目标由真实驱动读取本台适配和当次页面的通过项；点击还须安全框、
当前校准、输入开关、租约及接触前几何检查，不再要求逐按钮写旧档并启用。

首次登记、适配采样及运行比对都使用 v3 完整屏幕域，不对匹配输入应用缩略或 CLAHE。
定位先在当前已选粗框内检测候选和拟合屏幕边缘，再还原原图偏移并做严格姿态核验、
摆正及局部匹配。框外屏幕不参与候选，框内多候选拒绝；粗框过紧导致最佳可信外缘
被边界门排除时明确报错，不静默换成内缘、不自动扩大用户区域。
多个页面可通过或页面分差不足时
不选择最高分猜测。局部区域必须完整，OCR 尺寸、文字框与实际裁图对应；
空输入参考必须与当前裁图同尺寸，禁止广播或 resize 后把不完整参考当空输入证明。
颜色用途 `foreground/background` 必须明确且满足原证据颜色差门槛，
完整元数据可用仍要求四态资料完整；运行按当前页的实际依赖取保存检查和当次检查交集，
失败项不被实时匹配自动恢复，无关失败项不阻止已核验的导航项。内容、颜色和空输入
参考在消费该类证据时核验。共享路径接受有效 `ready/motion_ready` 校准，不重加已取消
的输入验收；旧档 `screen_proof.binding` 默认仍要求 `ready`。

共享布局的 `profile_revision` 继续为正整数；`binding` 纳入校准及模板、适配、
粗框引用摘要，避免旧档案 revision=1 与新适配 version=1 被当成同一证据来源。
运行结果兼容新增 `template_ref/adaptation_ref/installation_region_ref`，
以及 `coordinateVersion: calibrated_camera.v1`；导航和内容框反投影回已校准相机域，
`frameW/frameH` 仍是相机原图尺寸。不会把完整屏幕小图坐标标成相机原图坐标。
版本、绑定或校准在一次观测中途变化时拒绝混合结果。

`camera.locate_text` 的共享来源规则：

- `account/messages` 分别定位列表入口/内容文字，实际裁图均来自本页已核验 `content`；
  `account` 还须当次识别为列表页。`conversation` 使用 `title`，`input` 使用 `input`。
- 显式 `full` 搜索摆正后的完整手机屏幕，不是相机背景；内部 OCR 标签映射为
  已支持的 `messages`，不把 `full` 原样交 Apple Vision。未命中不自动扩大范围。
- 可选 `roi` 和输出 `bbox/cameraX/cameraY` 均为校准相机域，`frameW/frameH`
  仍为原相机尺寸。先加裁图偏移，再以单应反投影；点击中心独立反投影，
  不取透视包围框中心，不提前叠加当前手机位移。动作时只补偿一次。
- OCR 尺寸不符、越界/截断、同名歧义及资料中途变化均拒绝；精确未命中返回
  `found=false` 和原帧元数据，不返回坐标。快速恢复完整保留来源、坐标系及版本引用。
  这些引用提供可追溯性，不单独证明客户身份或授予动态行点击权限。

## 入口

8792 调试台“页面识别与发送证据”：

- `GET /api/screen-proof`：读取本设备档案与失效原因。
- `POST /api/screen-proof/reference`：保存人工确认的页面稳定特征。
- `POST /api/screen-proof/regions`：保存标题、输入框、内容区域和色样。
- `GET /api/screen-proof/check`：只取当前画面证据，不输入、不点击、不发送。

遵循现有设备上下文；写入带 `deviceId/contextId/operator/confirmed`。
参考另带 `state/label/region`；区域另带 `regions/inputEmptyConfirmed=true`。
区域坐标为当前相机像素 `{x1,y1,x2,y2,frameW,frameH}`，不是机械坐标。
区域键及中文名称：

| 键 | 中文 |
|---|---|
| title | 标题，只包含姓名，不含状态栏、按钮或聊天正文 |
| input | 空输入框，不含发送按钮、话筒按钮或键盘 |
| content | 消息内容区，不含标题、输入框和键盘 |
| foreground_sample | 己方文字气泡的无文字纯色小块 |
| background_sample | 聊天背景的纯色小块 |

机械臂会话不一致、租约占用、上下文失效、摄像头不推流、尺寸不符、无辨识特征、
区域重叠或颜色相近均拒绝。保存不连接串口、不修改校准、不执行物理动作。

`GET 8788/v1/devices/{device_id}/screen-proof` 仅返回元数据：
`registered/usable/revision/reference_states/regions_registered/blocking_reasons`。
不向 WX 返回区域坐标或参考图。`usable` 只说明档案完整且可解析，
不等于设备已在线、微信发送验收通过或业务已授权。
共享布局可用时，同一接口返回 `reference_states: ["conversation", "wechat_main"]`
并带上述三个版本引用，`revision` 是适配选择的递增修订号。接口只核持久资料和绑定，
不抓图、不输入、不执行动作；真实每帧识别仍须独立核验。已选共享资料不可用时
返回 `usable=false` 和中文阻断原因，不读取旧档案作为替代。

## 运行能力

插件声明 `camera.observe_regions`，参数 `{}`；设备也必须授权该能力。
真实摄像头通过设备 CameraBroker 采集单帧，帧源设备、物理相机、绑定版本、
分辨率和帧号必须匹配。返回：

- 契约版本、设备/摄像头编号、档案版本、绑定摘要。
- 原始帧号、采集时间、哈希及该帧归档证据编号。
- 页面状态和置信度；局部标题文字和局部 OCR 置信度。
- 输入框 OCR、是否与登记的空输入框一致。
- 已登记前景色的连通色块：范围、OCR、是否截断、左侧状态区是否空白。

只提供观测，不返回“微信已发送”。色块及布局不能可靠识别时返回不确定或异常，
不得以全帧正文命中兜底。图像及 OCR 数据仅限受控证据和调用方任务。

## 微信发送解释

1. 输入前必须确认目标标题、当前会话页和输入框为空。
2. 点击发送前采集证据，输入框可见正文必须与批准原文一致。
3. 只点击一次发送；之后最多读取四次证据，不重试点击。
4. 新增己方色块正文精确匹配、原画面无同文色块、输入框清空、标题不变、
   无失败/加载图形、至少两个递增帧号的稳定结果，才确认客户端发送效果。
5. 原有同文、仅输入框命中、标题变化、校准/档案变化、低置信度、截断、旧帧、
   气泡遮挡或证据不足，一律未知，不重复发送。

“已确认”证明手机客户端新增该条己方文字消息，不保证对端已经阅读，
也不替代微信服务端送达回执。长文本超出可见区域、特殊主题、图片/表情、
复杂背景及录制截图之外的布局仍需现场验收，不能降低证据门槛。

若发送证据已成立但后续返回或停靠失败，回调保持 `status=unknown`，
同时携带 `provider_message_id/sent_at` 与 `home_check.send_confirmation`，
明确“发送已确认，收尾待核对”，禁止重发。此扩展使用 v1 已允许字段，
不修改原任务终态，也不把整轮工作流伪报成功。
