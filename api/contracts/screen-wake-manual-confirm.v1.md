# 人工唤醒单次现场确认契约

版本：`screen-wake-manual-confirm.v1`。这是第 9.3 节"人工无姿态例外"的独立
后端确认通道，不是新的唤醒任务类型，也不属于 `screen-wake.v1` 的任务载荷。

## 用途与边界

手机暗屏（或全黑）且当前手机姿态不可观测时，自动唤醒不盲动（等待）。
只有本地操作员在现场核对"手机仍处于所展示参考位置、探头与移动路径安全、
只执行一次双击"并主动提交本确认后，**绑定的那一个唤醒任务**才允许使用
确认记录冻结的参考变换执行一次双击。

- 本确认只豁免该任务的**实时手机姿态**；不豁免新鲜源帧、当前机械坐标/Z/
  停车路径、急停、租约、未知结果或任务有效期门禁。
- 确认通过不产生运动。运动仍由原 `screen-wake.v1` 任务在租约与执行门禁内
  下发；消费后的授权不得透传为任意点击/滑动许可。
- WX 自动调度、插件和普通任务提交凭据不得调用；`operator_id` 只作一致性
  核对与审计，不作认证。当前部署不能隔离操作员控制通道时本接口整体禁用
  （配置 `screen_wake_manual_confirm_enabled`，默认 `false`，禁用时返回 403）。
- 旧 `screen-wake.v1` 请求中的布尔 `confirmed=true` 没有服务端确认记录时
  绝不自动获得本例外（规范 §9.3(7)）。

## 接口

`POST /v1/devices/{device_id}/screen-wake/manual-confirmations`

请求（`additionalProperties=false`，未知字段一律 400）：

| 字段 | 说明 |
| --- | --- |
| `contract_version` | 固定 `screen-wake-manual-confirm.v1` |
| `task_id` | 绑定的 `screen-wake.v1` 唤醒任务编号 |
| `idempotency_key` | 原唤醒任务的幂等键，须与任务一致 |
| `binding` | 复用 `screen-wake.v1` 的完整绑定结构，须与任务及当前校准一致 |
| `reference_evidence_id` | 服务端只读准备并展示的参考证据标识；不接受请求直接提供参考坐标或变换 |
| `operator_id` | 操作员标识（仅核对与审计） |
| `reason` | 非空文本确认说明 |
| `correlation_id` / `client_request_id` | 现有写操作审计字段 |

所有文本字段必须非空。参考证据由服务端按当前合格唤醒点、绑定与已发布校准
基准（或同基准下最后一次已验证姿态）计算；没有持久参考姿态记录时，参考来源
固定为已发布校准基准并明确标注，不冒充实时已验证姿态。

### 成功

- 首次确认：HTTP `201`，正文仅含 `contract_version`、`confirmation_id`（服务端
  生成的 ≥128 位随机标识）、`task_id`、`expires_at`（确认后 60 秒与任务到期
  时间中的较早者）。
- 相同 `client_request_id` 且同一请求重复提交：HTTP `200` 返回原记录，
  不延长有效期。

### 错误

| 状态 | 条件 |
| --- | --- |
| 400 | 字段/格式错误、未知字段、文本为空 |
| 403 | 操作员确认通道未启用（默认），或请求上下文不可信 |
| 404 | 设备或任务不存在 |
| 409 | 绑定、引用、同 `client_request_id` 异内容、任务状态冲突、跨设备 |
| 410 | 已过期的准备/确认引用 |

所有错误只返回原因，不创建运动任务。

## 消费

Fleet 在唤醒能力受理边界按任务编号/幂等键读取服务端记录并**原子消费一次**
（内存持久化，服务重启即失效——未消费确认自然撤销）。同一任务重提只查原
任务结果；其他任务、另一设备或摘要不匹配一律拒绝。确认过期、绑定/参数/坐标
基准变化都撤销尚未消费的确认；已消费记录保留用于对账。

执行结果在唤醒任务 detail 中标注 `manual_position_confirmed=true`、
`position_reference=manual_frozen_reference`，不伪造实时 `pose_status=verified`。
