## 1. Executive Summary

### 1.1 v1.1 的关键修订

v1.0 最大的实施风险是允许 Coding Agent 把 Camera -> Screen Homography 和 Screen -> Arm Affine 放在同一批点击样本中同时学习。这样会把相机误差、机械映射误差、机械运动误差和手机触点误差混在一起，尤其无法安全处理当前的 `2/5` 案例。

v1.1 强制改为三个阶段：

```text
Phase 0: 只用 Camera target detection + known target screen coords 拟合 H
         -> H VALIDATED -> H LOCKED

Bootstrap Check + First Click Gate
         -> 只允许中心点作为第一次真机自动点击

Phase 1: H LOCKED，只用 Effective Robot XY + Actual Touch 拟合 Arm Affine
         -> Arm Affine VALIDATED -> Arm Affine LOCKED

Phase 2: H LOCKED + Arm Affine LOCKED，做完整闭环和独立验证
         -> candidate promotion -> READY
```

### 1.2 当前能力判断

当前代码已经具备：

- Camera 取帧和 OpenCV 绿色标靶检测。
- Camera Pixel -> Screen Pixel Homography。
- Screen Pixel -> Arm XY 仿射逆解。
- daemon `XY/Z/TAP` 动作和 `Idle` 响应等待。
- 8788 手机真实触点回报、`sampleId`/`sequence` 匹配和超时处理。
- 当前三方误差计算和 calibration bundle 落盘。

当前缺少：

- Bootstrap Check。
- First Click Gate。
- H/Arm Affine 分阶段锁定。
- 只让 Actual Touch 更新 Arm Affine 的严格样本规则。
- candidate profile 隔离、自动收敛、回滚和完整迭代历史。

当前实际 bundle `/Users/ye/Desktop/WX/arm_fleet/data/devices/arm-01/calibration_bundle.json`
的 `status` 是 `draft`，不是 `ready`；其中虽然存在 `robotToScreen`、H 和 Z 字段，
但 `camera.visualVerify.passed=false`，不能把它当作已验证的 READY 基线。自动流程必须把
它视为只读 seed，先做 Bootstrap 和门禁检查；没有合格 seed 时进入
`BOOTSTRAP_REQUIRED`，不能凭空开始第一次机械臂点击。

### 1.3 当前 `2/5` 的实施影响

最近一次 5 点验证中：

```text

top_right:   touchVsTarget = 71.6 px
```

### 2.3 当前坐标和数学事实

- Camera Pixel：OpenCV 解码帧像素，原点左上，X 向右，Y 向下，当前 `1280x720`。
- Screen Pixel：K40 校准页 root-local 像素，原点左上，X 向右，Y 向下，当前 portrait `1080x2320`。
- Arm：daemon `MPos`，单位毫米；XY/Z 指令使用相对 `G91`。
- Z 正方向：向下、靠近屏幕；Z 负方向：向上、离开屏幕。
- Arm X/Y 现场物理方向和安全 XY 边界不能仅由当前代码推导。
- 当前没有相机内参/畸变系数，也没有显式 rotation/crop/resize 校正。
- 当前 MPos 是控制器位置估计，不是独立物理位置反馈。

## 4. Design Principles

1. H 和 Arm Affine 必须分阶段学习，不能同批样本无约束同时更新。
2. H 只由 `Camera Pixel <-> Known Target Screen` 学习。
3. Arm Affine 只由 `Effective Robot XY <-> Actual Touch Screen` 学习。
4. Actual Touch 永远不能直接更新 H。
5. `cameraError > threshold` 只能触发相机层重采/调查，不能直接断言并自动更新 H。
6. 任何异常样本都不能进入 READY profile 的正式模型。
7. 第一次真机自动点击必须走 First Click Gate，只允许中心点。
8. 自动 runner 只能操作 candidate；旧 READY 文件不可被原地污染。
9. Z 语义统一为 `zSafe` 和 `tapDepth`，禁止在实现中混用绝对 `zClick` 与相对 `tapDepth`。
10. MPos 只能作为 controller position check，不能被写成 physical position feedback。

## 5. State Machine

| State | 进入条件 | 执行动作 | 成功条件 | 失败条件 | 下一状态 |
|---|---|---|---|---|---|
| `IDLE` | 没有 active run | 等待 start | 收到 start | 重复/非法 start | `PRECHECK` |
| `PRECHECK` | A session active | 检查 binding、camera、急停、手机、Z、park | 全部通过 | 缺字段/会话变化 | `SAFE_PARK` 或 `ABORT` |
| `SAFE_PARK` | `zSafe` 和 park 已确认 | 先抬至 zSafe，再移 park XY | MPos 命令残差合格、画面无遮挡 | 超限/位置不符 | `PHASE0_CAMERA` |
| `PHASE0_CAMERA` | 手机校准页 active | 按 9 点显示绿色目标并检测 | 9 点 H 质量全部通过 | 目标缺失/外点/H 不稳定 | `H_LOCKED` 或 `ABORT` |
| `H_LOCKED` | Phase 0 通过 | 冻结 H model version | H 不再被 Arm 样本更新 | H 质量失效/相机移动 | `BOOTSTRAP_CHECK` 或 `CAMERA_RECALIBRATION` |
| `BOOTSTRAP_CHECK` | H 已锁定 | 不点击地检查 9 点预测和安全范围 | 全部满足 bootstrap 规则 | 旧模型不足以安全预测 | `FIRST_CLICK_GATE` 或 `BOOTSTRAP_REQUIRED` |
| `BOOTSTRAP_REQUIRED` | Bootstrap 失败 | 重新 Phase 0 或要求人工确认 | 重新建立可用 H/Arm 起点 | 无法建立安全起点 | `ABORT` |
| `FIRST_CLICK_GATE` | H 锁定、中心目标可见 | 只显示 center、预测、移动、TAP、收集触点 | 中心点通过 | 中心异常/触点超时/位置不符 | `PHASE1_ARM` 或 `ABORT` |
| `PHASE1_ARM` | First Click 通过 | 按 9 点采集 Arm/Touch 样本 | Arm Affine candidate 质量合格 | 异常/模型变差 | `ARM_LOCKED` 或重采样 |
| `ARM_LOCKED` | Arm Affine 通过 | 冻结 Arm model version | 独立验证前不再学习 | Arm 质量失效 | `PHASE2_VALIDATE` |
| `PHASE2_VALIDATE` | H/Arm 均锁定 | 完整 Camera->Screen->Arm->Touch | 全局条件满足 | 分类为 camera/arm/hardware | 对应重校准或 `FAILED` |
| `INDEPENDENT_VALIDATE` | Phase 2 通过 | 执行不同于拟合点的 5 点 | 全部通过 | 任一点失败 | `E_ACCEPTANCE` 或 rollback |
| `E_ACCEPTANCE` | 几何验证通过 | 文字/候选点击后等人工确认，再执行删除并等人工确认 | 两项逐项确认通过 | 取消、超时或验收失败 | 全部通过后自动 `PROMOTE`，否则不保存 |
| `PROMOTE` | candidate 所有门禁通过 | 原子提升 candidate | `status=ready` | 写入失败/绑定变化 | `READY` 或 rollback |
| `ABORT` | cancel、急停、不可恢复异常 | 停止、抬 Z、尽力 park、保存原因 | run 结束 | 停止异常 | 结束，旧 READY 保留 |

## 6. Bootstrap Calibration

### 6.1 目的

旧模型可能已经存在数百像素的区域性误差，不能把旧模型当作第一次自动点击的可信导航器。Bootstrap 是点击前的无接触安全筛选。

### 6.2 Bootstrap 输入

```text
当前/候选 H
当前/候选 Screen -> Arm Affine
9 个已知 target screen 坐标
当前 camera target detection
屏幕安全边界
机械允许范围
zSafe 和 SAFE PARK 配置
```

### 6.3 Bootstrap 检查

对每个 bootstrap 点：

```text
Camera Pixel C_i
-> H(C_i) = Predicted Screen P_i
-> robot_from_screen(P_i) = Predicted Arm R_i
```

检查：

1. `P_i` 为有限值，位于屏幕安全区域。
2. `R_i` 为有限值，位于允许机械范围；当前代码无法推导范围，必须由现场配置提供。
3. `R_i` 与当前 MPos 的位移不超过现有 `_goto_robot()` 的 300 mm 硬限制。
4. H 在 9 点上没有外点、极点、折叠、边界发散或单调性异常。
5. 如果存在可用的旧模型对比，旧/新模型在 9 点上的最大预测差异不超过配置值。
6. 任何点的预测落到屏外、机械不可达或模型不可逆，状态为 `BOOTSTRAP_REQUIRED`。

特别规则：Phase 0 只产生 Camera -> Screen H，不能从 Camera 数据单独产生 Screen -> Arm
映射。如果活动 profile 没有可用的 `xy.robotToScreen` seed，或者该 seed 无法通过
Bootstrap，则不得尝试“先点击再学习”；必须先通过人工 C 流程或其他已批准的现场方式
建立初始 Arm seed，之后才能进入 First Click Gate。

Bootstrap 不执行 TAP，不使用 Actual Touch，不修改模型。

### 6.4 当前 `2/5` 如何处理

如果旧 bundle 出现 `bottom_left≈575.7 px`、`top_right≈71.6 px`、`bottom_right≈137.9 px`，不允许直接进入 9 点自动点击。必须先重新执行 Phase 0 Camera Calibration；如果 H 仍不通过，保持 `BOOTSTRAP_REQUIRED`。

## 7. First Click Gate

### 7.1 强制流程

```text
PRECHECK
-> SAFE PARK
-> Phase 0 H Calibration
-> H LOCKED
-> BOOTSTRAP CHECK
-> CENTER ONLY
-> Camera Detect
-> Predict Screen/Arm
-> Safe Position Check
-> Z_SAFE
-> MOVE XY
-> Verify MPos
-> TAP
-> WAIT ACTUAL TOUCH
-> Check center error
```

### 7.2 通过条件

中心点必须同时满足：

- Camera 检测连续帧稳定。
- H 投影在屏幕安全区。
- 预测 Arm 在配置的机械安全范围。
- `postMoveMPos` 与命令目标误差不超过 `positionToleranceMm`。
- 收到 exactly one 个匹配 Actual Touch。
- `touchErrorPx <= targetTolerancePx`。
- 没有触点尺寸/方向变化、daemon session 变化或急停。

### 7.3 失败处理

中心点失败时：

- 不进入下一个点。
- 不更新 H。
- 不更新 Arm Affine。
- 不继续自动点击。
- 保存完整 sample 为 rejected。
- 抬到 `zSafe` 并尽力 SAFE PARK。
- 状态进入 `FAILED` 或 `ABORT`。

## 8. Camera Detection

### 8.1 当前实现事实

实际链路：

```text
motor_debug_server.detect_green_with_frame()
-> screen_edge.detect_green_target()
```

当前算法：BGR -> HSV、`inRange`、3x3 开运算、7x7 闭运算、`findContours(RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)`、面积 `>200`、最大轮廓质心。

阈值：

```text
H 68..98
S 55..255
V 35..255
```

当前失败重试：等待约 1.2 秒，每 0.2 秒取帧，默认约 3 秒，返回第一帧成功，不做多帧平均。

### 8.2 v1.1 检测门禁

保留当前函数返回兼容格式，但自动 runner 必须包装为稳定检测：

```text
detect_confirm_frames = 3       # CONFIGURABLE
center_jitter_px = 8             # CONFIGURABLE
area_delta_ratio = 0.20          # CONFIGURABLE
detect_timeout_s = 3.0            # 当前默认
```

建议成功条件：连续 3 帧检测到目标，中心两两距离不超过 8 px，面积相对变化不超过 20%，并且检测中心位于屏幕 ROI 内。3/8/20% 是建议初值，必须通过现场帧统计后冻结。

多个绿色候选的选择顺序：合法面积 -> 目标尺寸/长宽比接近历史 -> 跨帧稳定 -> 与预期位置接近 -> 面积最大。仍不能唯一确定时返回 `target_ambiguous`，禁止点击。

## 9. Camera -> Screen Model

### 9.1 Phase 0 的唯一学习数据

H 只能使用：

```text
Camera target detection: (cameraX, cameraY)
Known target screen coordinate: (screenX, screenY)
```

H 禁止使用：

```text
Actual Touch
MPos
tap result
Arm Affine residual
```

### 9.2 数学模型

```text
sx = (h00*cx + h01*cy + h02) / den
sy = (h10*cx + h11*cy + h12) / den
den = h20*cx + h21*cy + h22
```

继续复用 `fit_camera_to_screen()` 和 `CameraScreenTransform.screen_from_camera()`。

### 9.3 H 质量门禁

第一版 H candidate 必须满足：

- 旧手动接口可接受至少 4 点；自动 Phase 0 必须严格使用预先固定的 9 点计划，
  坐标见 Appendix A，不得由前端临时生成。
- RANSAC 可以用于诊断外点，但规则网格的任一点被排除时，candidate 无效。
- `inlierCount == pointCount`。
- `inlierRatio == 1.0`。
- RMS 不超过当前 `CAMERA_REPROJECTION_MAX_PX=3.0`，作为 INITIAL TARGET。
- 最大重投影误差也必须记录并通过配置阈值。
- 不能出现极点、分母接近 0、折叠或区域发散。
- 屏幕边界四角和网格内部映射保持顺序/单调性。

4/5 inlier 必须是 `INVALID`，不能是成功。不得为降低 RMS 静默剔除 bottom_left。

### 9.4 H 锁定

Phase 0 通过后保存：

```text
hModelState = LOCKED
hModelVersion += 1
hLockedAt
hSource = screen_target
```

Phase 1 和 Phase 2 不得因单次 Actual Touch 改写 H。只有显式进入 `CAMERA_RECALIBRATION`，重新完成 Phase 0，才允许生成新 H。

## 10. Screen -> Arm Model

### 10.1 数学定义

逻辑层仍称为 Screen -> Arm，但当前代码真正拟合和落盘的方向是
`robotToScreen`：`Effective Robot XY -> Actual Touch Screen`。运行时通过
`calibration_bundle.robot_from_screen()` 求其逆，得到 Screen -> Arm；第一版不得
另建一套独立的反向矩阵。

继续使用当前二维仿射：

```text
screenX = a*robotX + b*robotY + c
screenY = d*robotX + e*robotY + f
```

逆解：

```text
det = a*e - b*d
robotX = ( e*(screenX-c) - b*(screenY-f)) / det
robotY = (-d*(screenX-c) + a*(screenY-f)) / det
```

函数：`geometry.fit_affine()`、`calibration_bundle.robot_from_screen()`。

### 10.2 Arm Affine 唯一学习数据

Arm Affine 只能使用：

```text
Effective Robot XY
<->
Actual Touch Screen
```

其中：

```text
if postMoveMPos is valid
and ||postMoveMPosXY - commandedXY|| <= positionToleranceMm:
    Effective Robot XY = postMoveMPosXY
else:
    reject sample
```

明显运动异常样本不得进入拟合。

### 10.3 不使用的数据

以下数据不能作为 Arm Affine 正式学习样本：

- 只有 `commandedXY`、没有 `postMoveMPos` 的样本。
- MPos 残差超限样本。
- Actual Touch 缺失、错配、重复或屏幕尺寸不一致样本。
- Camera 检测不稳定样本。
- Phase 0 H 未锁定时采集的自动样本。
- 被分类为 `camera_measurement_error`、`ambiguous` 或 `hardware_investigation` 的样本。

### 10.4 Arm Affine 锁定

Phase 1 通过后保存：

```text
armModelState = LOCKED
armModelVersion += 1
armLockedAt
```

Phase 2 不允许边验证边同时更新 H 和 Arm Affine。

## 11. Camera -> Arm Optional Model

第一版不实现、不保存、不使用 `cameraToArmCandidate`。

主链路固定为：

```text
Camera Pixel
-> Camera -> Screen H
-> Screen -> Arm Affine inverse
-> Arm XY
```

只有在第一版主链路稳定、历史数据充分并另行审查后，才可以新增 Camera -> Arm 运行时优化模型。Coding Agent 不得因为 v1.0 文字中出现过该字段而实现它。

## 12. Error Classification

### 12.1 记录对象

每个 sample 必须记录：

```text
targetScreen T
cameraPixel C
cameraPredictedScreen P = H(C)
predictedArm R_pred
commandedArm R_cmd
postMoveMPos R_mpos
effectiveRobotXY R_eff
actualTouch A
```

### 12.2 误差公式

```text
cameraProjectionErrorPx = ||P - T||
touchTargetErrorPx      = ||A - T||
cameraTouchGapPx        = ||A - P||
armMotionErrorMm        = ||R_mpos - R_cmd||
```

`totalErrorPx` 默认等于 `touchTargetErrorPx`，不能把多个误差重复相加。

### 12.3 分类规则

分类的作用是决定样本进入哪个模型、是否重采样或人工调查；分类本身不能自动同时修改多个模型。

| 条件 | 分类 | 学习动作 |
|---|---|---|
| 检测跨帧不稳定/多候选 | `camera_measurement_error` 或 `ambiguous` | 不学习，重新检测/重采样 |
| H 已锁定但 `cameraProjectionError > targetTolerance`，且检测稳定 | `camera_transform_error` | 不学习 Arm，重新 Phase 0 |
| H 预测接近目标，但 `armMotionErrorMm > positionToleranceMm` | `arm_motion_error` | 不学习，抬 Z/停止/调查 |
| H 预测接近目标、MPos 合格，但 Actual Touch 超差 | `arm_mapping_error` 或 `touch_feedback_error` | 不更新 H；按触点和重复一致性区分 |
| Actual Touch 缺失/错配/尺寸变化 | `touch_feedback_error` | 新 sample 重试，旧 sample 不学习 |
| Camera、MPos、Touch 均不一致 | `ambiguous`/`hardware_investigation` | 不学习，停止自动 run |
| 三项均通过 | `ok` | 按当前阶段进入允许的模型 |

重要限制：`cameraProjectionError` 大、`cameraTouchGap` 小时，只能说明当前观察到的 Camera 判定与触点接近；它不是 H 错误的充分证明。只有 Phase 0 的独立标靶重投影和边界质量检查才能确认 H。

## 13. Model Update Algorithm

### 13.1 严格分阶段

```text
Phase 0:
    update H using camera target <-> known screen only
    validate
    lock H

Phase 1:
    keep H locked
    update Arm Affine using effective MPos XY <-> actual touch only
    validate
    lock Arm Affine

Phase 2:
    keep H and Arm Affine locked
    validate only
    failure routes to one designated layer
```

### 13.2 H 更新

- 新 H 只用当前 Phase 0 的所有合格 Camera/Target 配对全量拟合。
- RANSAC 外点不直接删除；需要重新显示、重新检测并替换对应点。
- 新 H 通过全点、RMS、最大误差、pole/fold/boundary/monotonicity 后才能锁定。
- Actual Touch 不得进入 H 拟合参数。

### 13.3 Arm Affine 更新

- 用所有合格 `R_eff <-> A` 样本全量重拟合。
- 新样本不使用更高权重；第一版等权，避免人为权重掩盖异常。
- 新 RMS 不得比上一稳定 candidate 明显变差。
- 单点异常只标记 rejected/outlier，不删除旧正式样本。
- 同一点最多重新采样 3 次；仍失败则 run failed。

### 13.4 Phase 2 失败时的更新规则

Phase 2 失败时必须先看锁定 H 的独立 Camera 质量和 Arm Motion：

```text
H 独立质量失败 -> CAMERA_RECALIBRATION
H 独立质量通过 + MPos/触点异常 -> ARM_RECALIBRATION 或 HARDWARE_INVESTIGATION
证据互相矛盾 -> ABORT，不自动学习
```

禁止 Phase 2 直接执行：

```text
同时 fit H + fit Arm Affine + 接受新模型
```

## 14. Convergence Algorithm

### 14.1 Initial Target

以下是第一版初始目标，不是永恒硬编码标准：

```text
xyRmsTargetPx = 3.0
pointTargetPx = 6.0
cameraRmsTargetPx = 3.0
```

这些值继承当前 `calibration_bundle.py` 的 `XY_RESIDUAL_RMS_MAX_PX`、`XY_RESIDUAL_MAX_PX`、`CAMERA_REPROJECTION_MAX_PX`。

### 14.2 PASS/SOFT_FAIL/HARD_FAIL

所有阈值必须配置化：

```text
0 .. targetTolerancePx:
    PASS

targetTolerancePx .. softLimitPx:
    SOFT_FAIL
    RESAMPLE / NO LEARNING

softLimitPx .. hardLimitPx:
    HARD_FAIL
    ABORT / INVESTIGATE

> hardLimitPx:
    HARD_ABORT
```

`hardErrorPx` 是安全停止边界，不是正常精度标准。

建议初值：

```text
targetTolerancePx = 6       # 当前验收门槛，CONFIGURABLE
softLimitPx = 30             # 建议值，需现场确认
hardLimitPx = 100            # 建议值，需现场确认
```

### 14.3 CONVERGED

一个 candidate 只有同时满足以下条件才算收敛：

1. Phase 0 H 全部 9 点无未处理外点。
2. Phase 0 H RMS <= `cameraRmsTargetPx`，最大误差 <= 配置上限。
3. Phase 1 Arm Affine RMS <= `xyRmsTargetPx`。
4. Phase 2 9 个闭环点的 `touchTargetErrorPx` 全部 <= `pointTargetPx`。
5. 5 个独立验证点全部 PASS。
6. 连续两轮没有新增 HARD_FAIL，且 RMS 改善小于 `0.5 px` 配置阈值。
7. H 和 Arm Affine model state 均为 LOCKED。

## 15. Anti-Divergence

强制机制：

1. 单次 `> hardLimitPx` 不学习并立即停止。
2. 连续 3 次异常进入 `ABORT`，次数可配置。
3. 新模型 RMS 变差超过容差时 rollback。
4. 新旧模型在 9 点网格上的最大预测差异超过配置上限时拒绝。
5. H 任意外点、inlier ratio < 1.0、pole/fold/boundary 失败时拒绝。
6. 同一点最多 3 次重采样。
7. `R_mpos` 与 `R_cmd` 超出位置阈值时不 TAP。
8. 预测 Arm 超出现场允许范围、位移超过 300 mm 或 Z 不安全时不运动。
9. cancel、急停、daemon session、camera binding、帧尺寸、手机方向/尺寸变化立即停止并使 candidate 失效。
10. 旧 READY profile 永远不被 candidate 原地覆盖。

## 16. Z Strategy

### 16.1 统一术语

第一版只在自动校准模型中使用：

```text
zSafe    = 绝对的会话 MPos Z 安全高度
tapDepth = 从 zSafe 向下的相对 TAP 深度
```

不新增 `zClick` 作为绝对高度。`hoverZ` 是当前旧代码字段，只作兼容字段；自动 runner 不把 `hoverZ` 和 `zSafe` 混为两个独立高度。

迁移规则：当前 `capture_hover_z()` 读取 `MPos.z` 并保存为 `hoverZ`，当前
`_goto_robot()` 还使用 `self.state["z"].get("hoverZ") or 2.0`。因此旧档案中的
`hoverZ=0.0` 会触发代码回退到 `2.0`，不能直接迁移为已确认的 `zSafe`，也不能从
数值本身推断安全性。迁移后的自动字段必须先保持 `zSafe=null`，由现场重新确认并
记录确认来源、时间和 daemon session；确认前自动 runner 不得 TAP。

推荐 profile：

```json
{
  "zSafe": null,
  "tapDepth": null,
  "tapFeed": null,
  "tapDwellMs": 0
}
```

只有人工确认后才能写入非 null 值。

### 16.2 自动动作

```text
当前状态 -> zSafe
-> XY MOVE
-> Verify MPos
-> TAP tapDepth
-> TAP 自动返回 TAP 前 Z，即 zSafe
-> 保持 zSafe
```

`arm_daemon3.py:474-496` 的 TAP 实际为：

```text
G91
G1 Z+depth
G4 P(dwell)
G1 Z-depth
G90
```

因此禁止在 `Z_CLICK`/下压状态横向移动。

### 16.3 当前 MPos 语义

daemon `Idle` 和 `MPos` 只能证明控制器接受并计算完成运动。当前没有独立 physical arm position feedback。实施中必须将字段命名为 `postMoveMPos` 或 `controllerPosition`，不能命名为 `actualPhysicalPosition`。

## 20. Calibration Contract

固定层间契约：

```text
Detector:
    Camera Frame -> Camera Pixel (x,y)

Homography:
    Camera Pixel -> Screen Pixel (x,y)

Affine:
    Screen Pixel -> Arm XY (mm)

Motion:
    Arm XY (mm) -> controller MPos (mm)

Touch:
    Phone ACTION_UP / MotionEvent -> Actual Touch Screen Pixel
```

| 层 | 坐标/单位 | 原点 | 正方向 | 有效范围 |
|---|---|---|---|---|
| Camera | `1280x720` px | 帧左上 | X右/Y下 | 当前解码帧 |
| Screen | `1080x2320` px | 手机校准页 root 左上 | X右/Y下 | `[0,w]x[0,h]` |
| Arm | MPos mm | 当前 daemon 会话坐标 | 由 MPos 正负定义 | 现场配置的允许范围 |
| Z | MPos mm | 当前会话 Z | 正方向向下 | daemon 软限位和现场配置 |

未来任何目标检测器，包括可能的外部识别器，只能输出 `Camera Pixel`，不能进入校准数学、模型选择或运动安全决策。

## 22. Model Lock State

### 22.1 H 状态

```text
UNINITIALIZED
-> CANDIDATE
-> VALIDATED
-> LOCKED
-> INVALID
```

### 22.2 Arm Affine 状态

```text
UNINITIALIZED
-> CANDIDATE
-> VALIDATED
-> LOCKED
-> INVALID
```

### 22.3 状态规则

```text
Phase 0: H CANDIDATE -> VALIDATED -> LOCKED; Arm 必须存在经过 Bootstrap 检查的 seed，
         否则保持 UNINITIALIZED 并进入 BOOTSTRAP_REQUIRED
Phase 1: H LOCKED; Arm CANDIDATE -> VALIDATED -> LOCKED
Phase 2: H LOCKED; Arm LOCKED; 只验证，不同时学习
```

摄像头移动、绑定变化、帧尺寸变化或屏幕边缘超容差时：

```text
H -> INVALID
candidate -> invalidated
```

## 23. Candidate / READY Lifecycle

```text
READY
-> AUTO START
-> CANDIDATE_CREATED
-> PHASE0
-> H_LOCKED
-> BOOTSTRAP
-> FIRST_CLICK
-> PHASE1
-> ARM_LOCKED
-> PHASE2
-> VALIDATING
-> PROMOTED
-> READY
```

失败：

```text
任意中间状态 -> FAILED/ABORT
                 -> candidate 保留为历史
                 -> 旧 READY 不变
```

`draft` 是未完成 profile，`ready` 是全部当前门禁通过的 profile，`invalidated` 表示绑定/会话/坐标空间失效，`failed` 只用于 candidate/run 结果，不得替换旧 ready。`acceptance.wechat` 仅为历史兼容字段，不是校准前置，也不控制 ready。

## 27. Recovery

| 故障 | 是否重试 | 样本/模型动作 | 最终状态 |
|---|---:|---|---|
| Camera frame unavailable | 3 次 | 不学习 | `ABORT` |
| target not detected | 当前点最多 3 次 | 不学习 | `RESAMPLE/FAILED` |
| target unstable/ambiguous | 3 次 | 不学习 | `ABORT` |
| phone touch timeout | 2 次新 sample | 不学习 | `FAILED` |
| sequence/sampleId 错配 | 0~1 次诊断 | 立即拒收 | `ABORT/INVALIDATED` |
| MPos 残差超限 | 不自动重发运动 | 不 TAP、不学习 | `ABORT` |
| daemon session changed | 不重试 | candidate 失效 | `INVALIDATED` |
| screen/camera binding changed | 不重试 | H 失效 | `CAMERA_RECALIBRATION` |
| H 外点/inlier ratio<1 | 重采样标靶 | H candidate 不接受 | `PHASE0_RETRY` |
| RMS 变差 | 增加/替换样本 | rollback | `RESAMPLE` |
| hard error | 不重试点击 | 抬 Z、park | `ABORT` |
| max iterations | 不继续点击 | 保留 failed candidate | `FAILED` |

## 28. Rollback

必须采用：

```text
活动 profile（可能是 READY，也可能是只读 draft seed）
-> candidate copy
-> Phase 0/1/2
-> validation
-> promote
```

任何异常点击、错误触点或拟合失败只影响 candidate。candidate 失败时记录：`runId`、`baseProfileHash`、`modelVersion`、`phase`、样本、旧/新 RMS、回滚原因和最后安全位置；若存在旧 READY，旧 READY 不变；若当前只有 draft seed，draft seed 也不被自动流程原地覆盖。
