## 1. 首次初始化顺序（规范 18.2）

1. **确认输入法客户端版本**：Android 客户端属于另一个工作区，不随本仓库构建交付。
   历史产物位置为 `AI_demo_更新/K40InputMethod/app/build/outputs/apk/debug/app-debug.apk`；
   不保证该路径、versionCode 或签名仍有效。安装前核对采样协议、版本、签名和回滚方案，
   确认原输入/删除、设备 ID 与服务地址保留。
2. **获取维护窗口，做一次完整机械校准**（原流程不变）。校准页稳定后新 APK 会自动上报页面元数据；校准完成（PROMOTE/finish）时自动生成坐标桥旁档
   `data/devices/{设备}/gesture_coordinate_frame.json`。
   - 元数据缺失时机械校准照常完成；上下滑/屏幕内部双击可从当前有效校准
     推导内部坐标，旧系统边缘坐标桥不能重新绑定。系统返回/Home 仍需真实
     页面元数据；损坏的坐标桥不会静默放行。手机采样和摄像头效果验收仍必需。
3. **查询并按需更新设备开关**（以下 PUT 仅为示例，不要按安装默认值覆盖现存设置）：
   ```sh
   curl http://127.0.0.1:8788/v1/devices/arm-01/automatic-gesture-settings
   curl -X PUT http://127.0.0.1:8788/v1/devices/arm-01/automatic-gesture-settings \
     -H 'content-type: application/json' -d '{
       "operator_id": "运维", "reason": "开启自动手势",
       "correlation_id": "init-1", "client_request_id": "init-1",
       "updates": {"automatic_gestures_enabled": true,
                    "auto_validate_after_calibration": true}}'
   ```
   四个开关：`automatic_gestures_enabled`（手势总开关）、`auto_validate_after_calibration`（校准后自动自检）、`automatic_navigation_enabled`（微信自动导航）、`gesture_program_enabled`（任意路径任务）。
4. **安装插件**（以下命令在 `arm_fleet/` 目录启动的 8788 服务上执行；
   `source_dir` 由服务端进程按其工作目录解析，已有同 ID 插件应走升级而非重复安装）：
   ```sh
   curl -X POST http://127.0.0.1:8788/v1/plugins/install -H 'content-type: application/json' \
     -d '{"source_dir": "examples/plugins/gesture-validation-adapter",
          "operator_id": "运维", "reason": "安装自检插件"}'
   curl -X POST http://127.0.0.1:8788/v1/plugins/gesture-validation-adapter/activate \
     -H 'content-type: application/json' \
     -d '{"operator_id": "运维", "reason": "启用自检插件"}'
   ```
   `gesture-program-adapter` 同法从 `examples/plugins/gesture-program-adapter` 安装并激活；
   `wx-wechat-adapter` 先查 `GET /v1/plugins`，按已安装状态选择 install 或
   `POST /v1/plugins/wx-wechat-adapter/upgrade`（`source_dir` 为
   `examples/plugins/wx-wechat-adapter`），遵守 §5 的排空要求。源码插件版本不等于
   当前服务实例加载版本，升级后核对插件查询结果和加载状态。
5. **跑一次自检**（先上下滑，再侧边返回，最后 Home；Home 需先登记桌面模板）：
   ```sh
   curl -X POST http://127.0.0.1:8788/v1/devices/arm-01/automatic-gestures/validate \
     -H 'content-type: application/json' -d '{"operator_id": "运维", "reason": "首次自检",
       "correlation_id": "v1", "client_request_id": "v1",
       "actions": ["scroll_up", "scroll_down"]}'
   ```
   以后每次新校准完成，若开关 2 已开，会自动排队一次（同 校准指纹+规则版本 只排一次）。
6. **查看资格**（WX/调试台同源）：
   ```sh
   curl http://127.0.0.1:8788/v1/devices/arm-01/automatic-gestures
   curl http://127.0.0.1:8788/v1/devices/arm-01/automatic-navigation/wx_chat_list_auto
   ```
   动作 `usable=true` 才可自动使用；`blocking_reasons` 给出中文原因。
   回顶需顶部专属模板（`top_proof_available`），Home 需桌面模板。

## 4. WX 侧

**WX 与 Fleet 分别选择和校验（2026-09-25）**：`HomeNavigation` 已改为每轮从 WX
事件库读取该设备的 `navigation-settings`，不再接受进程级开启参数。WX 的
`GET/POST /internal/devices/{device_id}/navigation-settings` 管理默认关闭的选择，
写入携带 `expected_revision`；Fleet 侧资格由校准门禁自动决定（设备开关已删除，2026-09-30）。两边都满足也不代替现场验收。

- WX 该设备的持久化选择 `automatic_navigation_enabled=true` 且 Fleet 资格满足后走新分支：
  提交 `wx_auto_navigate`（search_next/search_previous/return_top 单步编排；boundary_probe_pending 可继续下一步；top_verified=false 不算完成；8 步/90 秒预算耗尽 → top_not_confirmed）。
- 新 API：`ArmFleetClient.automatic_gestures() / automatic_navigation() / submit_auto_navigation() / close_navigation_run()`；404 **不回退**旧坐标档案。
- 返回上一级（back_to_list）：显式任务，必须携带与活动会话匹配的 `session_ref`；回到主页后沿用只读释放。
- WX 与 Fleet 的实际选择均关闭时走旧 `wx_list_navigate` 流程；
  不能仅凭安装默认值推断当前实例零变化。

## 5. 部署与升级顺序

- P1/P2：重载 8788 应用进程即可；不重启相机、不动 daemon。
- P3（PATH1）：获准维护窗口 → 停新任务 → 处理队列/unknown → **重启 arm_daemon3**（会话变化 → 按既有流程重新校准，不复用旧坐标）→ 插件排空升级 → 激活 → fake 验证 → 恢复。
- 插件升级规则：停新任务 → 队列清空 → `POST /v1/plugins/{plugin_id}/upgrade`
  （请求体提供新版 `source_dir`；保留旧版本目录供 rollback）→ 核对激活状态、
  install_dir 与内存加载摘要一致。原插件若已激活，升级实现会自动重新激活。
