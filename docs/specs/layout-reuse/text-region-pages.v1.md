# Optional reviewed text pages

The four legacy states remain the required prefix, in their existing order. A template may append up to eight unique `app_` states (12 pages total). Each extra page must explicitly declare `observation_kind: "text_regions.v1"`, a separate `ui_state` and `ui_state_display`. Legacy page semantics cannot be replaced. This is an opt-in extension of the existing layout records; existing four-page templates remain valid.

Extra pages use the same controlled two-frame evidence, reviewed anchors, region checks, calibration binding and freshness checks as legacy pages. A draft can add a page through its normal page PUT after controlled capture. An adaptation session fixes the page set from its published template; capture, review, preview, publication and rollback require every declared page. Page detection still requires one unambiguous match.

A text page requires unique reviewed `input` and `content` region purposes. Observation returns `text_regions` from the same selected frame, `text_region_coordinate_version: "calibrated_screen.v1"` and `text_region_frame_size`. Each region has root-screen `screen_bbox`, camera `bbox`, and OCR words in root-screen coordinates with camera `camera_bbox`. Both boxes use [left, top, right, bottom]. Confidence and truncation retain the OCR result. Text pages do not assert empty chat input or interpret chat bubbles. Business adapters decide the meaning of the reviewed text.

The existing `camera.locate_text(region="messages")` resolves to the reviewed content region and returns the existing immutable location evidence. Static target IDs remain template-defined. Neither path accepts caller coordinates as a replacement for reviewed target evidence.

Per-phone contact depth belongs only in adaptation `local_overrides`: a `kind: "target"` override for a template target with `mode: "tap"` can include `tapDepth` in millimetres. It retains the existing device stroke limit (0 < depth <= 10). The usual state, item, anchor, rectangle, evidence and reason fields remain required. The value reaches only that target's resolved click; other targets keep the device default. Depth is never stored in a shared template.

Per-target contact timing is optional in the same reviewed `local_overrides`: `tapDwellMs` is an integer from 0 to 2000 milliseconds, accepted only for `kind: "target"` and a template target with `mode: "tap"`. It is extra contact dwell, independent of travel time. The target override takes precedence over calibration `z.tapDwellMs`, including an explicit zero; omitted values keep the device default. Other targets and live IME geometry retain their existing timing. Invalid values or non-tap targets are rejected before motion. The adaptation publication permission, evidence and version checks remain required; task callers cannot override timing. This is an optional compatible field in `device-layout-adaptation.v1`, not a second calibration.
