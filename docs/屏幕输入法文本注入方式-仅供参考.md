# 屏幕文本输入方式：输入法候选栏下发（仅供参考）

> **定位声明**：本文描述本平台配套的一种文本输入方式——"输入法候选栏下发"。
> 它源自一次真实部署中验证过的做法，**仅供参考**：不是行业标准，也不排斥其他
> 方式（adb 输入、应用层直接集成、逐键点击等）。是否采用取决于你的现场约束
> （是否有目标设备的应用安装权、是否允许装输入法等）。

## 一、要解决的问题

机械臂指尖在手机屏幕上"打字"，最直觉的做法是逐键点击软键盘——但 26 键小
目标对机械臂极不友好：每次点击都要视觉确认，速度慢、误触率高、输入法弹窗
（联想/纠错）随时改变键位。正确思路是把**"写字"和"点按钮"分离**：

- 文本内容：由一个配套输入法经"候选栏下发"直接提交到焦点输入框；
- 机械臂：只负责点击"发送键"等大目标。

## 二、工作原理

```
业务系统（任何外部程序）
    │  提交文本输入任务（以 ime_device_id 定位目标键盘）
    ▼
平台屏幕输入法服务（Fleet HTTP 服务内嵌，设备侧 /api/v1/* 协议）
    │  登记任务，等待配套输入法来取
    ▼
手机上的配套输入法（iOS 自定义键盘扩展，源码随仓发行）
    │  经配对通道拉取任务（本机直连，或经 LAN TLS 代理跨机）
    ▼
键盘把文本上屏到焦点输入框（候选栏逐字提交，带拟人打字速度策略）
    │
    ▼
机械臂点击"发送键" → 摄像头取证（OCR/视觉判定）
```

## 三、组件与源码位置

| 组件 | 位置 | 说明 |
|---|---|---|
| Fleet 服务端 | `adapters/screen_ime/service.py`、`routes.py` | 输入任务的登记/下发/回收，随平台 HTTP 服务内嵌 |
| 输入任务模型 | `adapters/screen_ime/input_task.py` | 输入任务的类型、状态与生命周期 |
| **iOS 键盘完整源码** | `adapters/screen_ime/ios/` | Swift Package：`FleetIMEKeyboard`（键盘扩展本体）、`FleetIMEKit`（任务引擎/心跳/打字速度策略/字素拆分）、`FleetIMESelfCheck`（自检）、`FleetIMEDemo`；安装见 `ios/app/INSTALL.md` |
| 网页键盘页（K40 协议兼容） | `adapters/screen_ime/phone.html` | 浏览器端兼容实现 |
| 键位布局换算 | `adapters/screen_ime/keyboard_layout.py` | 机械臂确需点击键盘时的键位几何 |
| 配对身份库 | `runtime/ime_pairing.py` + `tools/init_ime_pairing.py` | 键盘与服务器的身份互认（离线建立信任） |
| LAN 加密通道 | `scripts/ime_lan_tls_proxy.py` | 键盘与服务器跨机时的 TLS 隧道 |

## 四、安全与边界

- 输入法通道**只认 `ime_device_id` 对应的任务**，不读取任何业务数据
  （无客户名单、无业务状态、无数据库访问）；
- 键盘与服务器经配对身份双向核验；跨机传输走 TLS；
- 机械臂与输入法职责严格分离：输入法只管"写字"，机械臂只管"点"。

## 五、快速复建

1. `tools/init_ime_pairing.py` 建立配对身份库；
2. iOS 设备安装 `adapters/screen_ime/ios/` 的键盘 App（见 `ios/app/INSTALL.md`），
   系统设置里把输入法切到本键盘；
3. 启动平台 HTTP 服务（输入法服务随之内嵌生效）；
4. 向 `ime_device_id` 提交文本输入任务，键盘侧拉取并上屏。

## 六、与其他方式的取舍

| 方式 | 优点 | 缺点 |
|---|---|---|
| **输入法候选栏下发（本方案）** | 整句提交、速度快、不依赖逐键视觉 | 需在目标设备安装配套输入法 |
| adb/无障碍注入 | 无需装键盘 | 需要 USB/调试授权，iOS 不适用 |
| 逐键点击 | 零侵入 | 极慢、误触率高、受输入法弹窗干扰 |
| 应用层集成 | 最可靠 | 需要改目标应用，多数场景不可行 |
