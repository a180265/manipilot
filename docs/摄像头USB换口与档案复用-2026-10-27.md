# 摄像头 USB 换口、独立绑定与人工校准恢复

## 问题与本次范围

2026-10-27 现场只读复现：换绑前置检查返回 `409 device_safety_unresolved`，原因是 `mechanical_safe=unknown`；Helper 丢弃服务端中文原因，只显示 HTTP 409。旧 cam-01 绑定仍指向离线 USB 接入。此次按用户确认修改：摄像头通道独立登记，调试台选择机械臂与通道对应；换口/换相机后由操作者完成校准，复用兼容的页面档案。不推断“还是同一摄像头”或免校准放行。

## 实现与使用

1. CameraHelper 刷新设备，选择当前完整 USB 标识，保存到 cam-01～cam-09（原有 cam-10 保持兼容），再启动该通道。摄像头登记不要求机械臂在线或机械状态已知；旧绑定可以替换。仍校验鉴权、通道、物理相机唯一占用、未完成写入和当前动作互斥，冲突显示具体中文原因与错误码。
2. 在调试台选机械臂，再选择相机通道并保存。只替换相机消费者，保留机械臂和输入法连接；目标设备暂停、退出托管并标记待校准，其他设备不变。相机已由另一机械臂使用时拒绝，先解除原对应再调整。此操作不恢复或重放旧任务。
3. 完成人工校准。旧来源/旧几何的校准不能授予新来源动作资格；新的帧身份进入校准检查，不再被启动时缓存的旧 USB 标识挡住。新校准完成后生成 `layout-recalibration.v1` 凭据，沿用当前选中且兼容的页面模板/适配，使用新测得的屏幕位置派生运行时几何。
4. 查看校准结果中的“页面资料沿用”提示，再按原流程启用设备和运行。模板、关键点、识别素材和历史版本不被改写；无需因为 USB 接口变化重采页面。换手机、页面尺寸/方向或输入法身份不兼容、资料损坏等仍需处理具体失效项。

## 隔离与兼容

- 换绑原子失效目标通道的旧帧、旧采集会话和旧代际回执；上传解码期间换绑，旧上传拒收。读取帧与身份头使用同一快照，不能配上另一来源的身份。
- 物理绑定与逻辑映射共用通道/设备互斥锁；实际动作占用仍会拒绝换绑。历史 unknown 任务不会因为摄像头登记而被改写或重试。
- `bindings.json` 中每条绑定新增可选 `bindingRevision`。旧文件兼容读取；首次写入将未修改通道的旧全局值固化，bind/renew 只推进目标通道值，rename 保持。通道 status、帧头和帧证据的 `binding_revision` 表示该通道修订；列表顶层及 health 的修订仍为全局诊断。修改其他通道不能使本通道校准失效。
- 校准完成记录绑定当前页面版本、摘要和新校准指纹；若之后换来源、改选页面版本或校准失效，旧复用记录不再适用。兼容自定义布局数据库和分离的校准目录。
- 旧来源的安装粗框可作为重新校准的搜索候选，只有 `needs_review/source_binding_changed` 放行；缺失、损坏等仍拒绝。正式运行仍使用本次校准的几何。
- 多通道原始取帧使用当前受信 v2 来源的实测宽高，不再用旧尺寸挡住新校准；运行时尺寸镜像随新鲜来源更新，正式动作仍比对新校准尺寸/几何。旧单路和直接摄像头模式保持原配置约束，不自动改变 Helper 的采集格式。
- 保存过的物理坐标动作/手势快照并非通用页面素材；其原有校准失效规则保留，不自动迁移旧动作。

## 页面复用结果（校准接口兼容新增）

`layoutReuse` 仅在人工 finish 或自动候选正式晋级后生成，由 state/finish/auto summary 返回；它不单独授予运动、托管或业务权限。

| status | 中文与含义 | 进入/退出及失败处理 |
| --- | --- | --- |
| ready | 页面资料已沿用 | 新校准完成且版本、尺寸、方向及手机身份兼容；下一次完成校准重算。 |
| not_selected | 无需沿用 | 无适用的已选页面资料；后续选资料并完成校准时重算。 |
| warning | 页面资料暂不能沿用 | 校准已保存，复用写入失败或资料不兼容；界面显示中文原因，人工处理受影响资料后再运行，不自动补采、不执行动作。 |
