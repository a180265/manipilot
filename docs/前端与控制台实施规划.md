# Arm Fleet 前端与控制台实施规划

版本：console-plan-v1，更新时间：2026-08-30。
适用对象：负责独立 Arm Fleet 项目的前后端 Agent。

本文是可直接实施的前后端交接基线。Agent 先完成仿真后端和仿真数据，再完成控制台，最后接入真实机械臂、摄像头和微信适配器。本文不改变 Arm Fleet 与 WX 的职责边界，前端不得绕过后端直接操作硬件。

现行规则注记：版本日期保留原规划基线，以下正文按屏幕证据入口、插件清单与
当前会话/列表导航契约消歧。平台控制台只管理硬件及执行；生产客户消息由 WX 从画面
解释并入库，旁观聊天不因发送完成自动退出。本规划不是部署或现场验收报告。

## 一、实现目标

交付一个可独立启动的 Arm Fleet 控制台，支持：

- 查看一台 Mac mini 上 10 个设备槽位的实时中文状态；
- 查看设备、机械臂、摄像头、微信账号、当前界面、任务、租约和健康信息；
- 按需打开只读实时画面，支持 WebRTC，无法使用时降级到 MJPEG；
- 查看任务步骤、证据、结果未知和人工处理原因；
- 执行暂停、恢复、隔离、解除隔离、安全状态检查/人工核对和全局急停等运维操作；
- 接收 WX 的已批准聊天发送任务，并回传三类结果；
- 为外部团队提供插件注册、安装、权限审查、运行监控和卸载能力；平台不内置拍照、巡检、刷视频、RPG 等具体业务任务；
- 通过固定 HTTP/JSON 契约与 WX fake 服务联调，前端不依赖 WX 数据库或代码。

控制台是设备运维界面，不是销售 CRM。不得出现客户画像、价格、档期、销售阶段、回复生成或发送许可按钮。

## 二、技术边界和目录

当前前端 React + TypeScript + Vite，后端 Python FastAPI；采用其他技术也必须保持
公开契约的 URL、字段、状态和错误语义。默认开发端口为 Fleet 控制台 5174、
WX 前端 5173、Fleet API 8788。8788 默认回环；输入法/多设备客户端需要访问时，
须显式配置 `ARM_FLEET_HOST` 与 `ARM_FLEET_ALLOW_LAN=1`，否则回落到回环。
只允许受控局域网，不得据此推定已有公网认证。daemon、8790 帧桥和 8792 调试台
默认保持本机监听，不作为手机访问入口。

Arm Fleet 后端是设备物理状态、租约、锁、屏幕动作和硬件急停的唯一可写事实源。观测桥提供摄像头/OCR 原始证据，WX 监听器负责微信业务确认；前端只显示后端查询结果，不保存可写设备状态，不直接调用 SDK、摄像头或 OCR。

## 三、前端信息架构

| 路由 | 页面 | 主要用途 |
|---|---|---|
| / | 设备总览 | 10 台设备状态、告警和快捷查看 |
| /devices/:deviceId | 设备详情 | 单设备状态、任务、证据、账号和实时画面 |
| /tasks | 任务中心 | 排队、执行中、已完成、明确失败、结果未知 |
| /takeovers | 人工处理 | 结果未知、隔离、归位失败和待人工确认 |
| /capabilities | 能力与插件 | 能力版本、权限、风险和测试状态 |
| /audit | 审计日志 | 操作人、时间、设备、任务和结果追踪 |
| /settings | 运行设置 | 契约、刷新频率、告警和版本信息 |

首屏直接进入设备总览。标题、按钮、状态、告警和空状态使用中文；协议键只在详情或调试抽屉中作为“内部编号”展示。

### 设备总览

采用响应式网格，设备卡高度固定，状态变化不造成页面跳动。每张卡展示设备编号、中文设备状态、微信账号及登录状态、摄像头状态、当前界面、当前任务、队列长度、最近心跳、最近画面时间、归位状态和最近告警。

卡片操作包括查看详情、查看实时画面、暂停设备、恢复设备、隔离设备、解除隔离和紧急停止。暂停、恢复、隔离、解除隔离和急停都要填写非空操作原因，不限语言，允许英文、数字和符号；危险操作必须二次确认。按钮按当前状态禁用，不能通过前端绕过后端状态机。

### 设备详情

分为“状态、任务、实时画面、证据、配置、审计”六个标签页。状态页显示机械臂连接、急停、摄像头质量、微信登录、当前界面、租约和版本；任务页显示步骤时间线、超时、证据、取消和结果；证据页显示截图引用、哈希、采集时间和归位检查；配置页默认只读；审计页记录所有运维操作。

结果未知必须置顶进入人工处理页。页面可打开实时画面、请求状态查询、标记已核对或隔离设备；打开画面本身不产生人工接管，规划要求选择具体会话、明确点击“人工接管”并再次确认后才向 WX 发出接管请求（当前 WX 前端缺口见第六节）。

## 四、中文状态模型

前端同时保存 key 和 display，渲染只使用 display。至少实现以下映射：

| 内部键 | 中文显示 |
|---|---|
| registered | 已注册 |
| starting | 启动中 |
| ready | 可用 |
| busy | 忙碌 |
| returning_home | 正在归位 |
| degraded | 降级 |
| offline | 离线 |
| paused | 暂停 |
| quarantined | 隔离 |
| maintenance | 维护中 |
| recovering | 恢复中 |
| confirmed | 聊天显示“已发送”，一般任务显示“已完成” |
| failed | 明确失败 |
| unknown | 结果未知 |
| valid | 有效 |
| expiring | 即将过期 |
| closed | 已关闭 |
| expired | 已过期 |
| unavailable | 画面不可用 |

平台展示的任务类型必须有中文名称。具体插件（例如 WX 的微信发送适配器或其他团队开发的应用插件）应在插件清单中提供 task_type 与中文名称；平台不得预置或硬编码某个应用的任务类型。英文键不能单独进入控制台、日志摘要、报告或模型输入。

## 五、后端 API

设备和任务接口：

    GET  /v1/devices
    GET  /v1/devices/{device_id}
    GET  /v1/devices/{device_id}/timeline
    GET  /v1/tasks?device_id=&status=&task_type=
    GET  /v1/tasks/{task_id}
    POST /v1/tasks/{task_id}/cancel
    POST /v1/devices/{device_id}/pause
    POST /v1/devices/{device_id}/resume
    POST /v1/devices/{device_id}/quarantine
    POST /v1/devices/{device_id}/unquarantine
    POST /v1/devices/{device_id}/home-check
    POST /v1/devices/{device_id}/reset-home
    POST /v1/emergency-stop
    GET  /v1/capabilities
    GET  /v1/audit-events

设备运维写操作必须带 operator_id、非空文本 reason（不限语言）、correlation_id 和幂等请求编号；
危险操作额外带 confirmation_token。任务提交、查看会话创建/续期/关闭遵守各自公开契约，
不能把运维请求字段强加给全部接口。返回对应操作或任务状态及审计关联；
错误同时返回 HTTP 状态、内部错误键、中文错误标题、中文处理建议和链路编号。

`home-check` 是平台安全检查，不是微信返回操作；当前无限位 daemon 设备停止并保持位置，
不执行 `$H`。`reset-home` 是有审计的人工确认，不替代校准或任务结果核对，也不点击应用主页。
机械臂安全状态、应用页面和业务会话状态应分开显示，不能用同一个“已归位”推定全部完成。

设备列表响应至少包含 device_id、设备中文名称、status 的 key/display、current_ui_state 的 key/display、wechat_account_id、camera_id、queue_length、last_heartbeat_at、state_observed_at、active_lease 和 alerts。镜像过期时显示“状态过期/需要人工确认”，不得当作可用。任务结果和入站界面状态也必须同时返回中文 display 字段，前端渲染不得从英文 key 临时翻译。

### 状态推送

优先实现 GET /v1/events/stream 的 SSE，事件至少包括 device.updated、task.updated、alert.created、system.emergency_stopped。SSE 不可用时前端每 3 秒轮询设备和任务接口。连接断开时显示“连接已断开”和数据更新时间，不能把旧数据标成实时。

### 实时画面查看

Arm Fleet 原生接口固定为：

    POST   /v1/camera/view-sessions
    GET    /v1/camera/view-sessions/{view_session_id}
    GET    /v1/camera/view-sessions/{view_session_id}/stream
    POST   /v1/camera/view-sessions/{view_session_id}/renew
    DELETE /v1/camera/view-sessions/{view_session_id}

创建接口必填 `device_id`、`purpose`（主动查看或接管查看）、`requested_by`、
`correlation_id`、`client_request_id`；`camera_id` 可选，传入时须与设备绑定相符，
前端为校验页面上下文应显式传入。续期与关闭分别由 POST/DELETE 路径指定会话；
请求体中的 `requested_by` 可省略，续期的 `correlation_id`、关闭的 `reason` 也可省略
（服务端有默认值）。当前实现返回 `camera-view.v1` 的 `status` 与 `status_display`，
以及值可为 null 的 `last_frame_at`、`closed_at`、`close_reason`；Schema 未将后三项列为必填，
客户端不应把此实现细节误写为跨版本契约要求。前端校验返回设备/摄像头与当前页面一致，
不得自行拼接地址；渲染使用 `status_display`。请求校验及错误以当前 API 实现为准。

会话状态为有效、即将过期、已关闭、已过期；摄像头断开或帧超过阈值时显示“画面不可用”。默认有效期 60 秒，前端每 20 秒续期；页面卸载、切换设备、浏览器断开和倒计时结束都要尽力关闭，关闭失败由后端超时清理。一个设备同时最多 2 个查看会话，超限返回中文错误。查看会话不获取机械臂租约、不改变任务、不暂停 Outbox、不写 WX 业务事件，也不默认录制。

## 六、实时画面交互

1. 初始只展示最近证据和“查看实时画面”按钮，不自动打开摄像头。
2. 点击后显示“正在建立查看会话”，请求后端创建。
3. 校验设备编号和摄像头编号一致后加载流；WebRTC 使用播放器组件，MJPEG 使用图片流组件。
4. 画面角标显示设备编号、摄像头编号、最新帧时间和“实时”；帧超时显示“画面不可用”。
5. 显示剩余时间和“延长查看”；续期失败时提示会话即将结束，不无限重试。
6. 关闭画面调用关闭接口并清理播放器；关闭不追加人工接管。
7. 只有选择具体 `conversation_id`/`customer_id` 后明确点击“人工接管”并二次确认，才调用
   Arm Fleet `POST /v1/takeovers` 转发到 WX 接管接口并暂停约定范围自动化；设备编号本身不能代替会话上下文。
8. 旧截图只能放在最近证据区域并标注采集时间，不能放进实时画面容器。

**未实现缺口（2026-09-27 静态复核）**：第 7 步是规划和契约要求，不是现行 WX
前端的完成状态。[`CameraViewer.tsx`](../../frontend/src/components/CameraViewer.tsx)
点击“人工接管”后直接建立接管查看会话并请求接管，没有独立的再次确认步骤；
[`armFleet.ts`](../../frontend/src/api/armFleet.ts) 将 `confirmation_token` 固定为“确认执行”。
服务端接受该字面令牌不等于操作者已确认。补齐前，不能勾选人工接管二次确认的验收项；
应验证取消确认不会发出 `POST /v1/takeovers`，确认后才发出该请求。

## 七、与 WX 的适配

WX 浏览器不直接访问 Arm Fleet 原生地址。WX 后端对外提供以下适配层，由后端转发到 Arm Fleet：

    POST   /v1/arm-fleet/camera/view-sessions
    GET    /v1/arm-fleet/camera/view-sessions/{view_session_id}
    GET    /v1/arm-fleet/camera/view-sessions/{view_session_id}/stream
    POST   /v1/arm-fleet/camera/view-sessions/{view_session_id}/renew
    DELETE /v1/arm-fleet/camera/view-sessions/{view_session_id}

这里的两层地址不能混用：/v1/camera/... 是 Arm Fleet 原生 API；/v1/arm-fleet/camera/... 是 WX 控制台适配层。Arm Fleet 与 WX 的地址、鉴权、超时放环境变量，不能写死前端。

当前入站由 WX `ScreenReader`/`LiveObservationWorker` 消费 Fleet
`GET /v1/devices/{device_id}/screen-observation` 的原始图像/OCR 证据，完成一对一会话、
身份、消息游标、撤回及入库。Fleet 不主动生成生产客户消息；
`POST /v1/arm-fleet/customer-messages` 保留为 WX 接收受信入站消息的兼容入口，
不等于要求 Fleet 主动监听；插件 `capture_message` 则仅支持仿真，不是当前真机主链路。
HTTP 409 `calibration_invalid` 应显示校准操作建议，
不能误报为“缺少观测桥”或绕过校准。

出站由 WX 向 `POST /v1/tasks` 提交已授权任务。自动 `chat_send` 可复用匹配执行会话，
发送取证后退出；旁观 `wx_session_send` 发送后保留聊天，人工另行退出或切换。
手机已由人工返回主页时使用只读 `wx_session_release`，不补点返回、不移动机械臂。
主页有限巡检由 WX 调度 `wx_list_navigate`，只引用已登记档案；
Fleet 控制台不配置 WX 允许名单、选择客户或决定巡检/回复策略。

Fleet 前端只展示原文、队列、步骤和结果，不改写发送文本。已发送、明确失败、结果未知
三类结果必须可对账；发送已确认但退出/停靠失败时保留发送事实并提示收尾待核对，
不得显示成未发送或提供直接重发旧动作。WX 侧手动编辑/发送不受 DS/RAG 失败阻断，
硬件、会话目标与结果未知门禁仍须保留。

## 八、权限、错误和安全

默认同机部署；明确启用局域网后必须限制来源、维护防火墙及可信客户端范围。
后端区分只读、运维和急停权限，前端隐藏无权限操作，后端再次拒绝；角色字段和
二次确认是操作约束（当前 WX 前端人工接管流程尚未落实），不能宣称其本身已经提供客户端身份认证。错误至少覆盖设备离线、
摄像头不可用、校准无效、微信未登录、验证码/风控、租约冲突、参数无效、任务过期、
账号不匹配、会话不匹配、文字哈希不匹配、查看会话过期和系统急停。

前端不得把客户原文、截图地址、令牌或凭据写入 localStorage、普通日志或 URL 查询参数。任何错误不能渲染成成功；结果未知必须保持原值并进入人工处理。

## 九、联调夹具和测试

Agent 必须提供 10 台虚拟设备、录制摄像头画面、fake 微信窗口、fake WX API、三种发送结果脚本、实时画面可用/断开/冻结脚本，以及错账号、错会话、哈希不一致、租约冲突、重启和急停脚本。

自动化测试至少覆盖：10 台总览和中文映射；SSE、轮询降级、断线和过期提示；运维操作二次确认；任务筛选、时间线、取消和结果未知置顶；实时查看创建、设备/摄像头校验、WebRTC/MJPEG、续期、关闭、过期、画面不可用和并发上限；查看画面不产生人工接管；原生地址与 WX 适配层地址不混用；错误不渲染为成功；刷新、切页和服务重启后状态可恢复。

发布前用 Playwright 在桌面和窄屏检查设备卡不跳动、长中文状态不溢出、实时画面不被面板遮挡、危险按钮反馈清楚，并截取总览、详情、任务中心、实时画面和断线状态。

## 十、交付物和完成定义

独立 Agent 交付可独立启动的后端 API、运行时和前端控制台；OpenAPI 或等价接口清单、Schema 示例和环境变量说明；10 台虚拟设备与 fake 摄像头/机械臂/微信/WX 联调服务；真实设备驱动接口和未配置项清单；中文状态映射、错误字典、审计示例和故障注入报告；前端单元、接口和浏览器端到端测试。

完成标准：Arm Fleet 单独启动可管理 10 台仿真设备；实时查看全流程可用且不影响任务；
WX fake 可完成原始屏幕证据消费、自动/人工会话、有限导航和三类回执联调；
真实硬件缺少必要参数时停留在仿真/待确认状态；控制台、日志摘要、报告和测试说明
使用中文关键值。上述为软件验收标准，不证明真实服务、当前手机校准或十台真机已通过。
