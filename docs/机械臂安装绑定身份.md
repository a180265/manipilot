# 机械臂安装绑定身份

2026-10-18，WX 与独立 SDK 已双向实现。

`daemon:arm-01` 是控制台选择的服务端已登记资源编号，以前绑定更新只解析并保存地址，资源编号被丢弃；布局登记又以摄像头唯一 ID 代替缺失的机械臂身份，导致粗框、采集、草稿与运行绑定互相矛盾。

现在设备登记从实际配置中的设备编号、daemon 资源编号、daemon 地址和串口路径生成 `daemon-binding.v1:<SHA-256>`。这是**安装路由身份**，不是机械臂硬件序列号证明；相机 ID、当前帧或页面内容不参与生成。首次加载旧配置只补齐同一既有路由的身份，不改物理参数、绑定修订、校准档案或任何历史证据。

- `daemon_resource_id`：已登记 daemon 资源编号。默认来自当前配置的设备编号。绑定 API 继续接受现有 `daemon_binding_id="daemon:设备编号"` 选择器，服务端解析真实连接信息后持久化此字段。
- `daemon_binding_id`：安装身份。设备视图、绑定视图、粗框、布局采集、草稿与运行读取同一值。绑定视图增加只读 `daemon_resource_id` 和 `daemon_binding_id`；请求协议保持既有选择器格式。
- 真实 daemon 地址、串口路径、资源来源或设备槽位编号改变时重新生成安装身份。原绑定 API 的租约撤销、挂载、自检、版本更新及待校准机制继续生效。
- 串口重新打开生成新的 daemon session，机械动作继续受当前 session 与校准档案的一致性门约束。安装身份不替代会话、硬件在场或校准有效性。
- 粗框保存前重新核对机械臂身份，绑定已变则拒绝旧预览；粗框读取对旧身份标记待复核。缺少实际绑定信息时明确失败，不再使用摄像头 ID 补齐。

旧资料若曾保存摄像头 ID 作为 arm 身份，必须重新预览并保存粗框、重新创建布局草稿和采集页面，不能修改历史 JSON 或摘要冒充新证据。仅加载同一路由并补齐其确定性身份，不要求重复物理标定；若通过绑定 API 改了连接或重挂，则仍必须遵循原流程重新校准。

回归通过真实 TestClient API 验证旧配置初始化、选择器持久化、幂等重放、重启身份稳定、实际地址/串口变更失效，以及粗框预览、草稿采集与当前安装身份一致。测试仅使用临时配置、仿真驱动及合成帧。
