# Arm Fleet 通用硬件任务运行时规划

版本：runtime-plan-v2，更新时间：2026-09-04。
状态：独立平台实现规划。复制 arm_fleet 后，可在另一台 Mac mini 上独立接入机械臂；平台本身不绑定任何具体业务，微信聊天及其他应用均通过外部插件和适配器接入。

现行规则注记：版本日期保留原规划基线，本文已按当前源码与公开契约校正职责。

`screen-proof.v1.md`，以及 WX 的 `LiveObservationWorker`、`HomeNavigation`。
下方实施阶段是规划顺序，不是通过记录；当前部署、校准与现场状态见《实施目标与验收总表》。

## 一、微信聊天是三方适配

微信聊天拆成观测、业务和执行三段：

| 方向 | 负责项目 | 解决的问题 | 明确不做 |
|---|---|---|---|
| 摄像头/OCR 到 WX | CameraHelper/8790 供帧，Arm Fleet CameraBroker/屏幕证据接口，WX 主动消费 | 按设备返回原始帧、透视矫正图、OCR、置信度、采集时间、绑定信息和哈希 | Fleet 不生成生产客户消息、不做客户归并、白名单或发送决策 |
| WX 到 Arm Fleet | WX 生成，Arm Fleet 执行 | WX 完成身份、会话、白名单和业务判断；Arm Fleet 校验设备/账号/会话/正文哈希并执行 | Arm Fleet 不改文本、不换联系人、不决定是否发送 |

客户名称由 WX 从屏幕证据解释并校验；WX 负责稳定客户身份、名称历史、同名冲突、
一对一会话和销售机会归属。外部插件仅在执行指定任务时核对本地页面/账号/会话线索，
不把任务目标自证为客户身份。显示名称不能直接作为客户唯一身份；当前主链路不支持群聊。

双方同时开发：先用录制画面和 fake 服务联调，再接单台真机，最后扩展到十台。唯一跨项目边界是 api/contracts 下的版本化 JSON Schema 和 HTTP/JSON 接口；不共享数据库、Python 包、ORM、窗口句柄、坐标或 OCR 对象，只共享版本化观测、任务和结果契约。

## 二、目标和边界

运行时目标：一台 Mac mini 管理十个固定设备槽位；每个槽位可以绑定机械臂、摄像头及可选的外部应用适配器；所有外部任务统一经过参数校验、能力校验、权限校验、租约、步骤执行、证据、结果、清理、归位和审计。

Arm Fleet 不实现客户画像、销售阶段、价格/档期事实、回复生成、风格检索、发送许可、销售跟进或 WX 的业务重试策略，也不实现任何具体应用的业务流程。微信发送、拍照、录屏、桌面巡检、刷视频、简单 RPG 和文件处理都只能由外部团队依据插件接口独立开发；平台负责承载、隔离、调度和取证。

## 三、总体架构

```text
设备驱动 -> 设备代理 -> 能力注册 -> 任务插件 -> 通用运行时
机械臂/摄像头    心跳/锁       输入输出契约    chat_send 等   租约/证据/回执/归位
                                      |
                              版本化 HTTP/JSON
                                      |
                 WX：事件、客户、事实、草稿、审核、Outbox、跟进
```

分层职责：

1. 驱动层：封装具体 SDK，提供移动、点击、输入、截图、停止、安全状态检查和传感器读取；无限位设备禁止自动回零。
2. 设备代理：绑定一个槽位，维护心跳、界面状态、互斥锁、安全停机。
3. 能力层：登记能力版本、输入输出 schema、风险等级、数据范围和测试夹具。
4. 任务插件：由平台外部团队实现具体应用或业务流程；平台只校验插件声明、分配资源、执行生命周期并接收结构化结果。
5. 运行时：统一调度、租约、步骤游标、证据、结果、清理、归位和重启恢复。
6. API 和控制台：提供任务接口、状态查询、只读实时画面查看会话、审计和运维操作；控制台只显示中文业务状态。

## 四、设备、任务和结果模型

设备注册至少包含：device_id、mac_mini_id、arm_slot、camera_id、capabilities、driver_versions、config_version、status、current_ui_state、last_heartbeat_at、last_camera_check_at、lease_id 和隔离原因。wechat_account_id 是应用上下文，不是通用硬件自检或输入法连接的前置。账号与槽位变更必须暂停设备、处理未执行任务、二次确认、追加审计，再重新检查绑定、驱动和校准；应用页面由对应插件另行核对。

通用任务外壳至少包含：task_id、task_type、capability、device_id、idempotency_key、payload、expires_at、contract_version、correlation_id 和 policy_context。运行时内部再保存任务状态、尝试次数、步骤游标、取消请求、证据引用和错误类别。

任务结果至少包含：任务编号、中文结果、内部兼容值、步骤摘要、证据引用、设备状态、清理结果、归位结果、回报时间和错误类别。聊天任务必须符合 task-result.v1；非聊天任务不得伪造微信账号、会话或客户字段。

## 五、通用任务生命周期

```text
已提交 -> 参数校验 -> 能力/权限校验 -> 等待设备 -> 获取租约 -> 执行步骤
      -> 采集证据 -> 计算结果 -> 清理现场 -> 回到安全状态 -> 释放租约
      -> 已完成 / 明确失败 / 结果未知
```

不变量：

- 过期任务不得取得租约；同一 idempotency_key 只能产生一个任务效果。
- 同一设备同一时刻最多一个会改变界面或机械臂位置的任务；插件不能绕过运行时直接点击。
- 动作开始后取消必须先停止、清理和取证；断连或证据不足一律结果未知。
- 结果未知时暂停或隔离设备，先人工或状态查询确认，禁止自动重试。
- 崩溃后按任务记录、步骤游标和证据恢复，不能因重启重复点击或发送。

每一步包含步骤编号、动作、前置条件、允许能力、超时、重试策略、可逆性、成功判定、证据要求和清理动作。成功判定必须结构化，例如确认微信主界面、目标会话编号一致、文字哈希一致。

## 六、租约、并发和十设备调度

Arm Fleet 是设备物理状态、设备锁、租约、能力和健康状态唯一事实源；WX 只能提交业务任务并消费只读镜像。十台设备可以并行，但每台设备内部严格串行。微信发送必须回到产生消息的同一设备、同一微信账号和同一外部会话。非聊天任务必须声明能力和资源范围，不得抢占微信设备锁。

Mac mini 或 Agent 重启后按持久任务、租约和 daemon 会话执行恢复核对；旧执行者不得沿用失效租约。
设备逐台执行驱动、摄像头、绑定和校准检查，应用主页确认不作为平台通用自检前置。
未开始任务可按恢复规则处理，仍须检查到期时间，不能因设备恢复补做已经过期的动作；
动作已发生但结果不明进入人工，已完成任务等待回报对账。

## 七、能力注册和插件接口

能力注册至少包含：能力编号、中文名称、版本、设备类型、输入输出 schema、风险等级、数据范围、可中断点、清理动作和测试夹具。平台只内置与具体业务无关的基础能力（例如移动、停止、安全检查、截图、输入等抽象）以及实时画面查看；微信页面解释/发送或任何应用操作必须以独立适配器或插件接入，不得写死业务调度。

插件统一实现：

```text
validate(task, device_context) -> 参数和权限结果
plan(task, device_context) -> 不含坐标细节的步骤计划
execute_step(step, runtime_context) -> 步骤结果和证据
recover(failure, runtime_context) -> 恢复动作和安全结果
cleanup(runtime_context) -> 清理和归位结果
cancel(runtime_context) -> 停止结果
```

具体插件的动作白名单、次数/时长上限、数据范围和是否写入外部系统，必须由插件作者在插件清单中声明并由平台审核；WX 的用户白名单属于 WX 业务数据，不进入 Arm Fleet 运行时。所有插件都必须截图取证、声明清理/归位动作，并明确结果是否允许回传 WX。

## 八、微信适配器实施细节

Arm Fleet 的 `GET /v1/devices/{device_id}/screen-observation` 提供
`screen-observation.v1` 原始证据。WX `ScreenReader` 解释画面，`LiveObservationWorker`
负责已启动设备的客户发现、身份、基线、新消息和撤回；消息游标和去重归 WX，
不得恢复为 Fleet 按正文指纹自行生成生产 `customer-message.v1`。
外部插件保留的 `capture_message` 仅用于仿真兼容，真实设备在该路径会被拒绝。

会话执行按任务类型区分：

- 自动 `chat_send`：校验版本/到期/幂等、设备、账号、会话及正文哈希；携带 `session_id`
  时复用匹配的自动会话，不重复开聊；发送取证后返回主页、按已登记档案回顶、清除会话并停靠。
- 旁观 `wx_session_open`/`wx_session_send`：按人工选择打开并保留会话，原文发送后仍保留聊天。
  手动发送不等待 DS/RAG、草稿或业务事实处理；硬件资格、当前目标和结果检查仍不可省略。
- `wx_session_exit`：WX 在明确退出时下发，确认主页后清除会话；切换客户先退出再打开。
  手机由人工直接返回主页时，WX 核对新画面后下发只读 `wx_session_release`，不重复点击返回。
- `wx_list_navigate`：WX 的 `HomeNavigation` 调度有限翻页和回顶，只传登记档案编号/版本。
  旁观期间可以巡检主页，但不能因此自动打开、发送或退出客户聊天；无档案只发现当前画面。

每个动作任务使用短租约；保留聊天不等于一直占用硬件锁。输入、点击、导航或证据不确定时
停止并保留待核对状态，不换新编号重放。发送已证实但返回/停靠失败时，保留发送事实，
报告收尾待核对，不能提示未发送或自动重发。

平台 `home_check` 与应用退出、删除键悬停停靠、校准安全停车位是不同概念。当前
daemon 无限位设备的 `go_home` 只停止并保持当前位置，`home_check` 再核对状态和画面质量；
只读释放任务连停止和归位都不调用。不得下发 `$H/$HX/$HY/$HZ`，也不能用 `G92`
伪造安全原点。其他设备若确有硬件回零能力，必须另有明确硬件与安全验收依据。

实时查看走独立只读会话，不获取聊天任务锁、不暂停业务自动化、不默认录制；
过期或摄像头不可用时返回“画面不可用”。MJPEG 使用返回的短时流地址；
WebRTC 仅在部署具备约定信令/WHEP 支持时使用，不能把普通 GET 地址当作 WebRTC 接口。

## 九、安全、证据和日志

- API、设备和控制台权限边界分开。8788 默认监听 `127.0.0.1`；手机访问时显式设置
  `ARM_FLEET_HOST` 与 `ARM_FLEET_ALLOW_LAN=1`，否则配置会回落到回环。
  局域网监听不等于访问鉴权已经完成，部署须确认防火墙、来源限制和可信客户端边界，
  不得直接暴露公网；既有角色字段和二次确认不能被当作独立身份认证。
  daemon、帧桥和调试台默认留在本机。任何凭据不得进入任务正文、截图文件名或普通日志。
- 插件只能访问声明的数据和能力；非聊天插件默认不能读客户消息或发送文本。
- 客户原文、截图和发送证据使用受控引用与哈希；通用日志不写完整客户原文。
- 验证码、风控页、登录失效、摄像头异常，或当前任务所需页面/会话无法确认时禁止发送；
  已持有聊天的发送核对当前会话，不强制先返回主页。
- 全局硬件急停由 Arm Fleet 立即停止领取新任务，并通知 WX 暂停 Outbox 和跟进调度。

每个任务至少记录任务编号、设备编号、能力、步骤、时间、中文结果、错误类别、证据引用和哈希、归位检查、操作者或调用服务、关联编号。指标包括心跳、等待时长、执行时长、结果比例、归位成功率、摄像头异常率、账号/会话校验失败率和重复任务拦截率。

## 十、部署升级和测试验收

发布应包含程序、驱动、适配器、能力清单、设备配置、契约和回滚版本。升级顺序：停止领取新任务 -> 安全完成或中止任务 -> 处理结果未知 -> 备份配置和证据索引 -> 升级 -> 逐台自检/归位 -> 小范围恢复 -> 观察指标 -> 全量恢复。

测试覆盖：任务 schema、能力权限、状态迁移、幂等、租约过期、取消、重启恢复、十台虚拟设备、插件安装/卸载和资源隔离、主动实时查看、接管实时查看、查看会话过期/关闭、摄像头遮挡、断连、安全检查/停靠失败和急停。另覆盖自动与人工会话的不同退出规则、只读释放不运动、无档案不滑动、校准失效返回 409 以及无限位设备拒绝回零。每个外部插件还必须自行提供其应用流程、错误和数据边界测试；平台只验证插件不得绕过运行时、不得越权访问未声明资源。

完成定义：运行时、驱动代理、租约、队列、证据和控制台可独立启动；平台基础能力、插件生命周期和资源隔离通过仿真及真机验收；十设备并行、单设备串行、重启和急停通过；提供插件开发者可使用的 fake 设备、契约和示例；微信双向契约与 WX fake 适配器作为一个外部插件联调通过，但不成为平台内置业务；所有业务界面、日志摘要、报告和任务说明使用中文关键词；任一插件和平台均可独立升级与回滚。

## 十一、实施阶段

下表保留原规划的阶段字母，只说明实施依赖，不与总表当前 A-I 阶段逐项等同，
不用于推定任何阶段已通过。职责和退出条件按本文现行规则解释。

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| A 基础骨架 | 配置、设备注册、心跳、能力注册、结构化日志 | 十个虚拟设备显示中文状态 |
| B 运行时核心 | 队列、租约、锁、状态机、取消、恢复 | 重复 worker 不双执行 |
| C 证据安全 | 截图/哈希、权限、审计、急停、隔离 | 故障有人工路径 |
| D 微信适配 | 原始屏幕证据、WX 消费、自动/人工会话任务和结果契约联调 | fake 双向闭环及会话保留/退出边界通过 |
| E 单台真机 | 单臂、摄像头、微信账号 | 三类发送结果可对账 |
| F 十台设备 | 并发、控制台、升级回滚 | 长时间稳定性通过 |
| G 插件生态 | 插件清单、沙箱/权限、安装升级回滚、示例适配器和开发者文档 | 外部插件可独立开发，平台不绑定具体应用且不污染其他业务状态 |

先完成 A-D 再开始 WX M5 真机联调；E-F 是生产聊天基础；G 可并行，但必须使用独立任务类型和权限。
