# Arm Fleet 部署与环境变量说明

版本：deploy-v2  
原部署说明日期：2026-09-12

摄像头详细设计背景见[兼容实施文档](摄像头辅助程序与多设备调试台兼容实施文档.md)。
现行接口与行为以脚本、配置定义及[公开契约](../api/contracts/README.md)为准；下文的
“本项目显式”配置是这套本机部署约定，不是本次整理对正在运行的进程、端口或硬件状态的证明。
部署前核对实际启动参数和生效配置，尤其区分本机服务、可信局域网入口与公开网络。

## 一、正式组件与固定端口

| 组件 | 地址/端口 | 固定职责 |
|---|---|---|
| Arm Fleet 后端 | 默认 `127.0.0.1:8788`；本项目显式 `0.0.0.0:8788` | 运行时、输入法校准 API、业务设备代理；手机经可信局域网访问 |
| 多摄像头帧服务 | `127.0.0.1:8790` | 按 `camera_id` 接收和提供 JPEG 帧 |
| 电机调试台 | `127.0.0.1:8792` | 按设备完成运动调试、校准和验收 |
| arm-01 daemon | `127.0.0.1:8795` | 独占 arm-01 串口 |
| arm-02 daemon | `127.0.0.1:8796` | 独占 arm-02 串口；其余设备使用独立端口 |
| CameraHelper.app | 无监听端口 | 唯一打开 UVC 摄像头的进程，上传到 8790 |
| Arm Fleet 控制台 | 默认 `127.0.0.1:5174` | 设备与业务运维界面 |

WX 业务前端和服务也属于同机闭环，但不由 Arm Fleet 启动：

| 组件 | 地址/端口 | 固定职责 |
|---|---|---|
| WX 业务前端 | `127.0.0.1:5173` | 用户主页、会话、审核和发送状态 |
| `sales_bot` | 默认 `127.0.0.1:8787`；本项目显式 `0.0.0.0:8787` | WX 事件、审核、Outbox、接管和结果回报 |
| `pricing_service`（按需） | `127.0.0.1:8765` | 价格事实服务；未启动时不得宣称真实价格可用 |

以下是按需或临时服务，不属于业务主链，启动前必须检查端口：

| 服务 | 默认地址/端口 | 启用条件与冲突说明 |
|---|---|---|
| 手机触摸标定 `calibration_server.py` | `0.0.0.0:8791` | 只在现场标定期间临时启动；需要局域网访问，完成后关闭 |
| 摄像头高帧率预览 `camera_preview_server.py` | `127.0.0.1:8793` | 可选媒体平面；Arm Fleet 未启用时不启动 |
| 旧闭环标定 `camera_closed_loop_calib.py --serve-api` | `0.0.0.0:8788` | 旧调试工具；会占用 Arm Fleet 主端口，只能在 Arm Fleet 停止时单独运行，不得与正式后端并存 |

服务默认监听 `127.0.0.1`。本项目明确要求手机输入法及局域网客户端访问，
因此 Arm Fleet 使用 `ARM_FLEET_HOST=0.0.0.0`、`ARM_FLEET_ALLOW_LAN=1`、
`ARM_FLEET_PORT=8788`；WX 使用其启动参数显式监听 `0.0.0.0:8787`。
这只适用于可信局域网，不得映射或暴露到公网。重启时保留现有监听配置，
不能恢复回环默认值导致手机失联。daemon、8790、8792、8793 保持本机访问；
8791 仅在触摸标定期间临时开放，不作为长期业务 API。
正式多设备运行禁止 Arm Fleet、WX、调试台或其他脚本直接打开 UVC 摄像头。

## 三、正式启动顺序

必须按以下顺序启动：

1. 多摄像头帧服务；
2. CameraHelper.app（先保存各通道绑定，再启动采集并核对帧状态）；
3. Arm Fleet 后端（启动内置 daemon supervisor，按设备拉起监听进程）；
4. 电机调试台；
5. 在电机调试台中逐台人工点击“连接设备”（真正打开串口并生成新会话）；
6. Arm Fleet 控制台。

~~~bash
cd /Users/ye/Desktop/WX/arm_fleet

# 1. 正式多路帧服务；旧 /latest.jpg 默认关闭
./.venv/bin/python scripts/camera_frame_server.py

# 2. 打开唯一摄像头辅助程序；在应用内刷新、选择并保存绑定后启动采集
open tools/camera_helper/dist/CameraHelper.app

# 3. Arm Fleet 后端；监督器会按 devices.json 启动 daemon 监听进程，
#    但不会自动 CONNECT 或打开串口
export ARM_FLEET_WX_CALLBACK=http://127.0.0.1:8787
export ARM_FLEET_HOST=0.0.0.0
export ARM_FLEET_ALLOW_LAN=1
export ARM_FLEET_PORT=8788
./.venv/bin/python -m agent

# 4. 电机调试台：启动后逐台选择设备并人工点击“连接设备”
./.venv/bin/python scripts/motor_debug_server.py

# 5. Arm Fleet 控制台
cd console && npm install && npm run dev
~~~

增加 arm-02 时，先逐台核对并配置 `device_id`、`arm_slot`、`serial_port`、
独立 `daemon_addr`、`camera_id`、`camera_device_unique_id`、分路帧/状态 URL、
`ime_device_id` 和现场账号/手机绑定；CameraHelper 中另核对物理摄像头绑定。
监督器只在配置符合其要求时按设备启动独立 daemon，监听不等于 CONNECT，
更不等于校准、租约及业务门禁通过。故障排查时也可在确认端口占用后临时手动启动：

~~~bash
ARM_DAEMON_DEVICE_ID=arm-02 \
ARM_DAEMON_PORT=8796 \
ARM_DAEMON_SERIAL=/dev/cu.usbserial-实际编号 \
./.venv/bin/python scripts/arm_daemon3.py
~~~

禁止两台真实机械臂共用 daemon 端口或串口。

监督器状态可通过 `GET /v1/daemons` 查询；日志写入 `data/daemons/{device_id}.log`。
daemon 进程崩溃时监督器最多自动重启配置次数，并将对应设备置为离线、撤销租约、
清除旧 daemon session 和校准资格。重启后仍须人工 CONNECT，不能把监听进程存在误报为
机械臂已连接。

串口热插拔说明：未知串口只进入待登记，不会自动绑定；已登记且原绑定未变化的串口重新出现时，
设备管理器会受控执行 `attach/self-check`。如果 daemon 尚未完成 CONNECT、绑定指纹变化或自检失败，
设备仍保持离线/待人工，不能接收 WX 托管任务。这里的受控自动挂载不等同于自动回零或自动恢复托管。

## 四、CameraHelper 绑定

1. 首次打开 CameraHelper.app 时允许 macOS 摄像头权限。
2. 点击“刷新摄像头”。
3. 在 `cam-01` 行选择 arm-01 固定机位的物理摄像头。
4. 点击“保存绑定”；正在采集的通道须先停止，保存成功后才能启动。
5. 点击该行“启动”，确认 `GET /cameras/cam-01/status` 为 `streaming`。
6. 增加设备时按 `cam-02`、`cam-03` 顺序逐台保存绑定、启动和验证。

同一个物理 `device_unique_id` 禁止绑定到两个 `camera_id`。绑定保存于：

~~~text
data/camera_helper/bindings.json
~~~

CameraHelper、帧服务或 Arm Fleet 单纯重启不自动使视觉校准失效；物理摄像头身份、分辨率或屏幕边缘变化才触发失效。

## 五、真实设备配置

每台真机在 `configs/devices.json` 中逐项登记并现场核对；以下是字段示意，
尖括号须替换为该设备的实际绑定，不可直接作为已验收配置使用：

~~~json
{
  "device_id": "arm-01",
  "arm_slot": 1,
  "driver_mode": "daemon",
  "binding_mode": "real",
  "serial_port": "<现场核对的本机串口>",
  "baud_rate": 115200,
  "camera_id": "cam-01",
  "camera_device_unique_id": "<CameraHelper 中核对的物理摄像头 ID>",
  "camera_mode": "multi_channel",
  "camera_frame_url": "http://127.0.0.1:8790/cameras/cam-01/latest.jpg",
  "camera_status_url": "http://127.0.0.1:8790/cameras/cam-01/status",
  "expected_frame_width": 1280,
  "expected_frame_height": 720,
  "expected_frame_fps": 10,
  "daemon_addr": "127.0.0.1:8795",
  "ime_device_id": "<本机输入法设备 ID>",
  "wechat_account_id": "<WX 核对的账号绑定>"
}
~~~

多路正式运行由 CameraHelper.app 向 8790 分路上传，运行时按 `camera_frame_url`
选择 HTTP 帧源；当前 `arm-01` 配置不含 `camera_source_mode`，有有效分路 URL
也不会因未声明该字段而拒绝。Chrome 兼容上传属于显式单机降级，来源标记由帧服务
检查；`camera_source_mode=chrome_bridge` 不负责切换运行时帧源。只有无帧 URL 且显式
选择 `camera_source_mode=direct`（或 `legacy_single` 兼容模式）时才尝试直接采集 UVC；
多路模式缺少帧 URL 会被拒绝，不能靠猜测设备抢占摄像头权限。

设备配置加载时会拒绝重复 `device_id`、非空绑定字段的跨设备冲突、
真机缺少 `camera_id`、多路真机缺少 `camera_frame_url` 或分路 URL 指向其他 camera；
它不逐项强制所有真机字段齐全。daemon 监督器另检查本机 `daemon_addr` 和
`serial_port`，失败会报告配置错误；驱动与任务运行还有各自门禁。
缺失字段、占位账号或陈旧物理绑定不因配置加载成功而获得真机操作许可。

## 六、逐台校准与托管门禁

打开 `http://127.0.0.1:8792` 后：

1. 选择设备；
2. 页面建立包含 arm、camera、物理摄像头、daemon、会话和绑定版本的设备上下文；
3. 完成 Z、普通点击、长按清除、XY、摄像头映射及调试台输入法 E 验收：
   `ime_input_tap`（固定文字输入及候选点击）和 `ime_delete_clear`（删除清空）；
   微信测试会话不是通用校准前置；
4. 最终档案写入 `data/devices/{device_id}/calibration_bundle.json`；
5. 自动校准可在暂缓 E 验收时保存为 `motion_ready`，但不等同于完整 `ready`；
   补齐本轮两项 E 验收及其执行证据后才能提升为 `ready`。实际业务任务仍需
   实时绑定指纹、租约和各自的安全/资格门禁通过，不能只凭档案状态执行。

设备切换时旧上下文立即失效。错 camera、错 daemon、会话变化、分辨率变化、屏幕边缘偏差超过 8px 或上一动作结果未知时，自动任务必须被拒绝。
近黑画面属于 `camera_waiting`，暂停新动作并等待画面恢复；等待本身不代表
摄像头绑定或校准被撤销，恢复后仍要重新核对当前帧及动作资格。

## 七、环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `ARM_FLEET_HOST` | Arm Fleet API 监听地址 | `127.0.0.1` |
| `ARM_FLEET_ALLOW_LAN` | 是否允许 Arm Fleet 监听非回环地址；必须显式设为 `1`，否则自动回落到 `127.0.0.1` | `0` |
| `ARM_FLEET_PORT` | Arm Fleet API 端口 | `8788` |
| `ARM_FLEET_MODE` | `simulation` 或 `real` | `simulation` |
| `ARM_FLEET_WX_CALLBACK` | WX 回报基地址 | 空 |
| `ARM_FLEET_WX_COMPAT` | 是否显式启用 Arm Fleet 内的旧 WX 监听兼容插件；正式独立运行必须关闭 | `0` |
| `ARM_FLEET_SCREEN_IME` | 是否启用输入法适配 | 启用 |
| `ARM_DAEMON_DEVICE_ID` | 当前 daemon 所属机械臂 | `arm-01` |
| `ARM_DAEMON_PORT` | 当前 daemon TCP 端口 | `8795` |
| `ARM_DAEMON_SERIAL` | 手动启动 daemon 时独占的串口；监督器使用逐台 `serial_port` | 代码默认 `/dev/cu.usbserial-212420`（旧设备已退役，当前设备不得照用；须现场核对） |
| `ARM_FLEET_DAEMON_SUPERVISOR` | 是否启用 Arm Fleet daemon 进程监督 | 启用（仿真模式不启动真实进程） |
| `CAMERA_LEGACY_ID` | 显式启用旧单路接口 | 未设置，正式模式关闭 |
| `CAMERA_STALE_AFTER_SECONDS` | 8790 画面过期阈值（秒），可按现场调优 | `1.5` |
| `CAMERA_UNAVAILABLE_AFTER_SECONDS` | 8790 画面不可用阈值（秒） | `10` |
| `CAMERA_MAX_FRAME_BYTES` | 8790 单帧最大 JPEG 字节 | `8388608`（8MB） |
| `IME_BASE_URL` | 调试台访问输入法校准 API | `http://127.0.0.1:8788` |

## 八、单机兼容回滚

CameraHelper 暂时不可用时，只允许 arm-01 单机回滚：

~~~bash
./.venv/bin/python scripts/camera_frame_server.py --legacy-camera-id cam-01
~~~

同时必须把 arm-01 配置改为 `camera_mode=legacy_single`，frame URL 固定为 `http://127.0.0.1:8790/latest.jpg`，并禁用其他真实设备。两路以上画面存在时旧 `/latest.jpg` 返回 HTTP 409，禁止猜测使用哪一路。

兼容回滚补充（D 组）：
- Chrome 兼容页（`http://127.0.0.1:8790/`）上传帧必须带 `X-Frame-Source: chrome_compat`
  降级标记；正式 CameraHelper 帧带 `camera_helper` 标记，两者不允许同时写同一通道
  （来源冲突返回 HTTP 409 `camera_source_conflict`，正式来源优先）。
- 通道状态与取帧响应均含 `source`/`source_display`（中文显示来源）；
  `GET /cameras/{camera_id}/events` 可查绑定变更、来源切换/冲突、分辨率不匹配、
  画面过期/恢复与服务重启事件（同步落盘 `data/camera_helper/events.jsonl`）。
- 帧冻结判定的职责边界：8790 只提供帧序/接收时间/来源等原始事实；
  冻结判定由消费端 `RealCameraDriver` 完成（连续哈希一致且流序号未推进才判冻结，
  静态画面不误判），设备状态中的 `camera_source/camera_last_frame_at/camera_frame_age_ms`
  由运行时从帧源元数据回写。
- `scripts/g_live_motion.py`、`g_direction_map.py`、`tap_machine.py` 等旧脚本引用的
  `/latest.jpg` 属单路调试兼容用途，多设备业务必须使用 `/cameras/{camera_id}/...`。

## 九、持久化与备份

2026-09-09 安全补充：`RealArmDriver` / `PyserialGrblTransport` 及旧版 G 阶段
验收脚本默认禁止打开串口。只有人工停止对应 daemon、确认现场安全后，
才可为单次离线验收命令设置 `ARMFLEET_ALLOW_DIRECT_SERIAL=1`。
不要将此开关加入常驻服务环境；该开关是操作确认门禁，不替代串口占用检查。
正常调试台和业务运行时仍使用 daemon，不需要此开关。

daemon 的读写与位置查询现有超时保护；超时后丢弃物理会话和租约，
不自动 CONNECT、不重放动作。TAP 深度必须为正的有限数值且不超过 10mm，
停留必须为 0-5 秒（包含既有删除键长按范围）。
RESUME 现在要求同连接的运动租约且未急停锁定；STOP/ESTOP 仍独立优先。
修改代码不会更新已运行的 Python 进程：需在现场确认安全、停止操作后，
安排 daemon、调试台及使用驱动桥的运行时重启。重启后人工连接，重新确认标定。

升级前必须备份：

~~~text
configs/
data/armfleet.db
data/camera_helper/bindings.json
data/devices/*/calibration_bundle.json
data/devices/*/calibration_wizard.json
data/supervision/
evidence/
~~~

收藏和调试队列按设备保存于 `data/devices/{device_id}/`，不得复制到其他设备。
