# Manipilot 部署与环境变量说明

版本：deploy-v3（2026-10-12 随独立 SDK 重写；历史口径见 git）
接口与行为以脚本、配置定义及[公开契约](../api/contracts/README.md)为准；下文的
"显式"配置是本机部署约定，不是对正在运行的进程、端口或硬件状态的证明。
部署前核对实际启动参数和生效配置，尤其区分本机服务、可信局域网入口与公开网络。

## 一、正式组件与固定端口

| 组件 | 地址/端口 | 固定职责 |
|---|---|---|
| 平台后端 | 默认 `127.0.0.1:8788`；局域网部署显式 `0.0.0.0:8788` | 运行时、输入法校准 API、任务接口；手机经可信局域网访问 |
| 多摄像头帧服务 | `127.0.0.1:8790` | 按 `camera_id` 接收和提供 JPEG 帧 |
| 电机调试台 | `127.0.0.1:8792` | 按设备完成运动调试、校准和验收 |
| arm-01 daemon | `127.0.0.1:8795` | 独占 arm-01 串口 |
| arm-02 daemon | `127.0.0.1:8796` | 独占 arm-02 串口；其余设备使用独立端口 |
| CameraHelper.app | 无监听端口 | 唯一打开 UVC 摄像头的进程，上传到 8790 |
| 平台控制台 | 默认 `127.0.0.1:5174` | 设备与运维界面 |

按需或临时服务（启动前必须检查端口）：

| 服务 | 默认地址/端口 | 启用条件与冲突说明 |
|---|---|---|
| 摄像头预览面 `camera_preview_server.py` | `127.0.0.1:8793` | CameraHelper 的预览平面；推荐与帧服务同起 |
| 手机触摸标定 `calibration_server.py` | `0.0.0.0:8791` | 只在现场标定期间临时启动，完成后关闭 |
| 旧闭环标定 `camera_closed_loop_calib.py --serve-api` | `0.0.0.0:8788` | 旧调试工具；占用主端口，只能在后端停止时单独运行 |

服务默认监听 `127.0.0.1`。手机输入法及局域网客户端需要访问时，显式
`ARM_FLEET_HOST=0.0.0.0`、`ARM_FLEET_ALLOW_LAN=1`、`ARM_FLEET_PORT=8788`。
这只适用于可信局域网，不得映射或暴露到公网。daemon、8790、8792、8793 保持本机访问；
8791 仅在触摸标定期间临时开放。
正式多设备运行禁止平台、调试台或其他脚本直接打开 UVC 摄像头。

## 二、首次构建

~~~bash
cd <仓库根>
uv venv --python 3.11 .venv
uv pip install -e ".[server,real]" pytest pytest-xdist

# CameraHelper.app 构建产物已随仓发行（tools/camera_helper/dist/）；
# 仅当修改其源码后才需要重新构建：
cd tools/camera_helper && ./build_app.sh
~~~

应用包必须通过 `codesign --verify --deep --strict`，`Info.plist` 必须包含 `NSCameraUsageDescription`。

## 三、正式启动顺序

1. 多摄像头帧服务（宿主安装指纹缺失时会自动生成）；
2. 预览面（可选，推荐）；
3. CameraHelper.app（先注入环境变量，见下；GUI 内刷新/绑定/启动通道）；
4. 平台后端（内置 daemon supervisor 按设备拉起监听进程，不自动 CONNECT）；
5. 电机调试台（8792）——逐台人工点击"连接设备"（真正打开串口并生成新会话）；
6. 平台控制台（可选）。

~~~bash
cd <仓库根>

# 0) 摄像头链路凭据（部署态，data/ 不入库；缺失按 README"摄像头链路"节自举）
launchctl setenv CAMERA_CONTROL_TOKEN_FILE "$PWD/data/camera_helper/control.token"
launchctl setenv CAMERA_HOST_INSTALLATION_ID_FILE "$PWD/data/camera_source/host_installation_id"

# 1) 帧服务
./.venv/bin/python -B -m scripts.camera_frame_server --fleet-db data/armfleet.db --evidence-dir evidence/store
# 2) 预览面
./.venv/bin/python -B -m scripts.camera_preview_server
# 3) 摄像头辅助程序
open tools/camera_helper/dist/CameraHelper.app

# 4) 平台后端；监督器按 devices.json 启动 daemon 监听，但不自动 CONNECT
export ARM_FLEET_HOST=0.0.0.0   # 仅可信局域网需要
export ARM_FLEET_ALLOW_LAN=1
export ARM_FLEET_PORT=8788
./.venv/bin/python -m agent

# 5) 电机调试台
IME_BASE_URL=http://127.0.0.1:8788 ./.venv/bin/python scripts/motor_debug_server.py

# 6) 平台控制台
cd console && npm install && npm run dev
~~~

### 换绑安全门闭环（可选但推荐）

帧桥的绑定写（bind/unbind/renew）在安装锁内核对平台侧**设备安全视图**
（`GET /v1/devices/{id}/safety-view`，服务签名）。未配置密钥时按设计
fail-closed 拒绝换绑。启用闭环：

~~~bash
# 平台后端与帧桥使用同一份密钥文件
export FLEET_SAFETY_KEYS_FILE="$PWD/data/camera_helper/control.token"   # 平台侧验签
# 帧桥侧（客户端签名）：
export CAMERA_FLEET_SAFETY_BASE_URL="http://127.0.0.1:8788"
export CAMERA_FLEET_SAFETY_KEYS_FILE="$PWD/data/camera_helper/control.token"
export CAMERA_FLEET_SAFETY_KEY_ID="<密钥文件中的 key_id>"
~~~

增加 arm-02 时，先逐台核对并配置 `device_id`、`arm_slot`、`serial_port`、
独立 `daemon_addr`、`camera_id`、`camera_device_unique_id`、分路帧/状态 URL、
`ime_device_id` 和现场设备绑定；CameraHelper 中另核对物理摄像头绑定。
监督器只在配置符合其要求时按设备启动独立 daemon，监听不等于 CONNECT，
更不等于校准、租约及业务门禁通过。故障排查时可在确认端口占用后临时手动启动：

~~~bash
ARM_DAEMON_DEVICE_ID=arm-02 \
ARM_DAEMON_PORT=8796 \
ARM_DAEMON_SERIAL=/dev/cu.usbserial-实际编号 \
./.venv/bin/python scripts/arm_daemon3.py
~~~

禁止两台真实机械臂共用 daemon 端口或串口。

监督器状态可通过 `GET /v1/daemons` 查询；日志写入 `data/daemons/{device_id}.log`。
daemon 进程崩溃时监督器最多自动重启配置次数，并将对应设备置为离线、撤销租约、
清除旧 daemon session 和校准资格。重启后仍须人工 CONNECT，不能把监听进程存在误报为
机械臂已连接。

串口热插拔说明：未知串口只进入待登记，不会自动绑定；已登记且原绑定未变化的串口重新出现时，
设备管理器会受控执行 `attach/self-check`。如果 daemon 尚未完成 CONNECT、绑定指纹变化或自检失败，
设备仍保持离线/待人工，不能接收外部业务任务。这里的受控自动挂载不等同于自动回零或自动恢复托管。

## 四、CameraHelper 绑定

前置：`CAMERA_CONTROL_TOKEN_FILE` 与 `CAMERA_HOST_INSTALLATION_ID_FILE`
两个环境变量必须对 helper 进程可见（`launchctl setenv` 后经 `open` 启动，
或带 env 直接运行二进制；缺失时界面报"V2 认证失败/不可用"）。

1. 首次打开 CameraHelper.app 时允许 macOS 摄像头权限。
2. 点击"刷新摄像头"。
3. 在 `cam-01` 行选择 arm-01 固定机位的物理摄像头。
4. 点击"保存绑定"；正在采集的通道须先停止，保存成功后才能启动。
5. 点击该行"启动"，确认 `GET /cameras/cam-01/status` 为 `streaming`。
6. 增加设备时按 `cam-02`、`cam-03` 顺序逐台保存绑定、启动和验证。

同一个物理 `device_unique_id` 禁止绑定到两个 `camera_id`。绑定保存于：

~~~text
data/camera_helper/bindings.json
~~~

绑定也可以部署时经 `scripts.camera_binding_v2.save_binding_v2` 播种（脱离 GUI 的
自举方式，见 README"摄像头链路"节）。控制令牌与宿主安装指纹是部署态文件：
令牌经 `camera_binding_v2.generate_control_token` 生成；安装指纹为 36 位小写
UUID，帧服务启动时缺失会自动生成。

CameraHelper、帧服务或平台后端单纯重启不自动使视觉校准失效；物理摄像头身份、分辨率或屏幕边缘变化才触发失效。

## 五、真实设备配置

每台真机在 `configs/devices.json` 中逐项登记并现场核对；以下是字段示意，
尖括号须替换为该设备的实际绑定，不可直接作为已验收配置使用：

~~~json
{
  "device_id": "arm-01",
  "arm_slot": 1,
  "driver_mode": "daemon",
  "binding_mode": "real",
  "serial_port": "<现场核对的本机串口>",
  "baud_rate": 115200,
  "camera_id": "cam-01",
  "camera_device_unique_id": "<CameraHelper 中核对的物理摄像头 ID>",
  "camera_mode": "multi_channel",
  "camera_frame_url": "http://127.0.0.1:8790/cameras/cam-01/latest.jpg",
  "camera_status_url": "http://127.0.0.1:8790/cameras/cam-01/status",
  "expected_frame_width": 1280,
  "expected_frame_height": 720,
  "expected_frame_fps": 10,
  "daemon_addr": "127.0.0.1:8795",
  "ime_device_id": "<本机输入法设备 ID>"
}
~~~

业务插件如需账号绑定字段（例如按业务账号区分设备），由插件侧自行维护，
不进平台设备绑定表。入库的示例配置一律使用占位符（如
`/dev/cu.usbserial-XXXXXXXX`）；真机部署在本地修改后按文件名精确 `git add`，
不要整库 `-A`，避免把本机硬件标识带进公开历史。

多路正式运行由 CameraHelper.app 向 8790 分路上传，运行时按 `camera_frame_url`
选择 HTTP 帧源。Chrome 兼容上传属于显式单机降级，来源标记由帧服务
检查；只有无帧 URL 且显式选择 `camera_source_mode=direct`（或 `legacy_single`
兼容模式）时才尝试直接采集 UVC；多路模式缺少帧 URL 会被拒绝。

设备配置加载时会拒绝重复 `device_id`、非空绑定字段的跨设备冲突、
真机缺少 `camera_id`、多路真机缺少 `camera_frame_url` 或分路 URL 指向其他 camera；
它不逐项强制所有真机字段齐全。daemon 监督器另检查本机 `daemon_addr` 和
`serial_port`，失败会报告配置错误；驱动与任务运行还有各自门禁。
缺失字段或陈旧物理绑定不因配置加载成功而获得真机操作许可。

## 六、逐台校准与门禁

打开 `http://127.0.0.1:8792` 后：

1. 选择设备；
2. 页面建立包含 arm、camera、物理摄像头、daemon、会话和绑定版本的设备上下文；
3. 完成 Z、普通点击、长按清除、XY、摄像头映射及调试台输入法 E 验收：
   `ime_input_tap`（固定文字输入及候选点击）和 `ime_delete_clear`（删除清空）；
   业务会话不是通用校准前置；
4. 最终档案写入 `data/devices/{device_id}/calibration_bundle.json`；
5. 自动校准可在暂缓 E 验收时保存为 `motion_ready`，但不等同于完整 `ready`；
   补齐本轮两项 E 验收及其执行证据后才能提升为 `ready`。实际任务仍需
   实时绑定指纹、租约和各自的安全/资格门禁通过，不能只凭档案状态执行。

设备切换时旧上下文立即失效。错 camera、错 daemon、会话变化、分辨率变化、屏幕边缘偏差超过 8px 或上一动作结果未知时，自动任务必须被拒绝。
近黑画面属于 `camera_waiting`，暂停新动作并等待画面恢复；等待本身不代表
摄像头绑定或校准被撤销，恢复后仍要重新核对当前帧及动作资格。

## 七、环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `ARM_FLEET_HOST` | 平台 API 监听地址 | `127.0.0.1` |
| `ARM_FLEET_ALLOW_LAN` | 是否允许监听非回环地址；必须显式设为 `1`，否则自动回落 `127.0.0.1` | `0` |
| `ARM_FLEET_PORT` | 平台 API 端口 | `8788` |
| `ARM_FLEET_MODE` | `simulation` 或 `real`（受硬件确认表门禁约束） | `simulation` |
| `ARM_FLEET_TASK_CALLBACK` | 任务回报基地址（旧名 `ARM_FLEET_WX_CALLBACK` 兼容） | 空 |
| `ARM_FLEET_WX_COMPAT` | 旧业务监听兼容开关；**本仓不含对应监听文件，必须保持关闭** | `0` |
| `ARM_FLEET_SCREEN_IME` | 是否启用输入法适配 | 启用 |
| `FLEET_SAFETY_KEYS_FILE` | 平台侧设备安全视图验签密钥（与帧桥同文件） | 未设置=换绑安全门 fail-closed |
| `CAMERA_FLEET_SAFETY_BASE_URL` | 帧桥安全查询的平台基地址 | 未设置=换绑 fail-closed |
| `CAMERA_FLEET_SAFETY_KEYS_FILE` | 帧桥签名密钥文件（旧名 `ARMFLEET_WX_NAV_KEYS_FILE` 兼容） | 未设置 |
| `CAMERA_FLEET_SAFETY_KEY_ID` | 帧桥签名 key_id | `camera-frame-server` |
| `CAMERA_CONTROL_TOKEN_FILE` | 摄像头采集控制令牌（helper 与帧桥同文件） | 未设置=helper V2 不可用 |
| `CAMERA_HOST_INSTALLATION_ID_FILE` | 宿主安装指纹文件（36 位小写 UUID；缺失帧桥自举生成） | `data/camera_source/host_installation_id` |
| `CAMERA_HELPER_EXEC` | 受控 helper 二进制路径（帧桥时钟证明用） | 未设置 |
| `ARM_DAEMON_DEVICE_ID` | 当前 daemon 所属机械臂 | `arm-01` |
| `ARM_DAEMON_PORT` | 当前 daemon TCP 端口 | `8795` |
| `ARM_DAEMON_SERIAL` | 手动启动 daemon 时独占的串口；监督器使用逐台 `serial_port` | 代码默认值已退役，须现场核对 |
| `ARM_FLEET_DAEMON_SUPERVISOR` | 是否启用 daemon 进程监督 | 启用（仿真模式不启动真实进程） |
| `CAMERA_LEGACY_ID` | 显式启用旧单路接口 | 未设置，正式模式关闭 |
| `CAMERA_STALE_AFTER_SECONDS` | 8790 画面过期阈值（秒） | `1.5` |
| `CAMERA_UNAVAILABLE_AFTER_SECONDS` | 8790 画面不可用阈值（秒） | `10` |
| `CAMERA_MAX_FRAME_BYTES` | 8790 单帧最大 JPEG 字节 | `8388608`（8MB） |
| `CAMERA_SOURCE_RETENTION_TTL_SECONDS` | 来源帧保留 TTL（只留业务消费过的帧） | `900` |
| `IME_BASE_URL` | 调试台访问输入法校准 API | `http://127.0.0.1:8788` |

## 八、单机兼容回滚

CameraHelper 暂时不可用时，只允许 arm-01 单机回滚：

~~~bash
./.venv/bin/python scripts/camera_frame_server.py --legacy-camera-id cam-01
~~~

同时必须把 arm-01 配置改为 `camera_mode=legacy_single`，frame URL 固定为 `http://127.0.0.1:8790/latest.jpg`，并禁用其他真实设备。两路以上画面存在时旧 `/latest.jpg` 返回 HTTP 409，禁止猜测使用哪一路。

兼容回滚补充：
- Chrome 兼容页（`http://127.0.0.1:8790/`）上传帧必须带 `X-Frame-Source: chrome_compat`
  降级标记；正式 CameraHelper 帧带 `camera_helper` 标记，两者不允许同时写同一通道
  （来源冲突返回 HTTP 409，正式来源优先）。
- 通道状态与取帧响应均含 `source`/`source_display`；
  `GET /cameras/{camera_id}/events` 可查绑定变更、来源切换/冲突、分辨率不匹配、
  画面过期/恢复与服务重启事件（同步落盘 `data/camera_helper/events.jsonl`）。
- 帧冻结判定的职责边界：8790 只提供帧序/接收时间/来源等原始事实；
  冻结判定由消费端 `RealCameraDriver` 完成，设备状态中的
  `camera_source/camera_last_frame_at/camera_frame_age_ms` 由运行时从帧源元数据回写。

## 九、持久化与备份

`RealArmDriver` / `PyserialGrblTransport` 及旧版验收脚本默认禁止打开串口。
只有人工停止对应 daemon、确认现场安全后，才可为单次离线验收命令设置
`ARMFLEET_ALLOW_DIRECT_SERIAL=1`。不要将此开关加入常驻服务环境。

daemon 的读写与位置查询有超时保护；超时后丢弃物理会话和租约，
不自动 CONNECT、不重放动作。TAP 深度必须为正的有限数值且不超过 10mm，
停留必须为 0-5 秒。RESUME 要求同连接的运动租约且未急停锁定；STOP/ESTOP 独立优先。
修改代码不会更新已运行的进程：需现场确认安全、停止操作后，安排 daemon、
调试台及使用驱动桥的运行时重启。重启后人工连接，重新确认标定。

升级前必须备份：

~~~text
configs/
data/armfleet.db
data/camera_helper/bindings.json
data/devices/*/calibration_bundle.json
data/devices/*/calibration_wizard.json
data/supervision/
evidence/
~~~

收藏和调试队列按设备保存于 `data/devices/{device_id}/`，不得复制到其他设备。

## 十、发布前验证

~~~bash
cd <仓库根>
.venv/bin/python -m pytest tests/ -q -n 4
cd console && npm install && npx vitest run
~~~

CameraHelper 修改源码后必须执行 release 构建和签名校验。真实硬件最终验收必须至少使用两路摄像头和两个独立 daemon 完成串线阻断测试；没有两套硬件时只能声明软件测试通过，不能声明硬件在环完成。
