# Arm Fleet 独立 Agent 实施交接清单

版本：agent-handoff-v1，更新时间：2026-08-30。
用途：将 `arm_fleet/` 交给不了解 WX 内部代码的独立开发 Agent 时，作为开工前置条件、实现边界和验收清单。

现行规则注记：版本日期保留原交接基线；本文正文已按屏幕证据接口、WX 观测/巡检调度、
外部插件的当前 `manifest.json` 及 `wx-session.v1`、`wx-list-navigation.v1` 契约校正。
本清单规定要交付和验证的内容，不声明当前服务、单台或十台真机已经通过。

## 一、结论和使用方式

`通用硬件任务运行时规划.md` 已经定义了完整的软件流程和跨项目边界；本清单补充硬件接入时不能凭空猜测的输入。

独立 Agent 必须先完成“输入确认表”，再实现驱动和真机动作。没有确认的硬件参数不得自行假设；应先接入仿真驱动，或将该项标记为“待确认”并阻止真机动作。

## 二、已冻结、不得自行修改的内容

以下内容是架构契约，不因机械臂品牌或摄像头型号改变：

- Arm Fleet 是机械臂、摄像头、微信窗口、物理租约、设备锁、归位和硬件急停的唯一事实源。
- WX 是客户、会话、销售机会、价格事实、回复草稿、人工审核、发送许可、Outbox 和跟进的唯一事实源。
- 双方只通过 `api/contracts/` 下的版本化 JSON Schema 和 HTTP/JSON 接口通信。
- 机械臂项目不能访问 WX 数据库、Python 内部类、UI 坐标或客户主数据。
- 微信发送必须使用 WX 已批准的原文；Arm Fleet 不改写文本、不换联系人、不自行重试。
- 动作后无法确认结果时必须返回“结果未知”，不能猜成“明确失败”。
- 自动 `chat_send` 按计划发送后退出；旁观 `wx_session_send` 保留聊天，退出是独立操作。
- Fleet 提供原始帧/OCR 与执行证据；客户身份、允许名单、消息游标和主页巡检调度由 WX 负责。
- 当前无限位 daemon 设备不执行 `$H` 回零；安全检查、应用返回和删除键悬停停靠分别记录。
- 8788 默认回环，手机访问可显式启用受控局域网；启用监听不等于已完成访问鉴权。
- 十台设备可以并行，每台设备内部严格串行。
- 控制台、人工队列、日志摘要、报告和任务说明使用中文；英文只作协议键、编号或内部兼容值。

## 三、必须由项目方提供的硬件输入

在真机开发前填写下表。若一项不适用，明确填写“不适用”；不得留空。

| 输入项 | 必须明确的内容 | 未明确时的风险 |
|---|---|---|
| 机械臂型号 | 品牌、型号、自由度、负载、工作范围 | 驱动 API、动作边界和安全限位无法确定 |
| 机械臂 SDK | SDK 名称、版本、语言、安装方式、授权方式、示例工程 | 无法实现移动、停止、安全检查和错误分类 |
| 连接方式 | USB、串口、网口、蓝牙或其他；端口分配和通信参数 | 十台设备无法稳定发现和隔离 |
| 坐标与标定 | 设备坐标、摄像头/屏幕坐标、校准流程、安全高度、软件原点及有效会话 | 点击位置、安全停靠和运动范围不可验证，不能猜测或执行无限位回零 |
| 摄像头 | 型号、分辨率、帧率、接口、固定方式、视野范围、光照 | 无法确认主界面、账号、会话和发送证据 |
| Mac mini 环境 | 芯片、macOS 版本、屏幕数量、分辨率、权限策略 | 窗口控制、屏幕采集和驱动兼容性不确定 |
| 微信环境 | 微信版本、登录方式、窗口布局、账号数量、是否允许辅助功能 | OCR、窗口定位和账号隔离无法实现 |
| 网络与服务 | Arm Fleet/WX 地址、端口、`ARM_FLEET_ALLOW_LAN`、防火墙、来源限制和鉴权边界 | 无法进行双向 API 联调；不能把局域网监听误当作身份认证或公网授权 |
| 账号绑定 | 设备编号、槽位、摄像头、微信账号的一一对应表 | 可能错账号或错会话发送 |
| 急停 | 机械臂急停方式、断电策略、软件停止接口、人工恢复流程 | 故障时无法保证人员和设备安全 |
| 证据保存 | 截图保存位置、保存时长、哈希算法、访问权限、脱敏要求 | 无法完成发送和归位审计 |

## 四、独立 Agent 的实现顺序

以下 A-G 保留原交接清单编号，属于实施顺序，不是当前验收状态；阶段状态以总表为准。

### 阶段 A：只做仿真，不接真机

交付：配置加载、设备注册、能力注册、虚拟摄像头、虚拟机械臂、任务队列、租约、状态机、结构化日志和中文状态映射。

验收：十个虚拟设备可注册；同一设备不会并发执行；重复 `idempotency_key` 不重复执行；任务过期、取消、重启恢复和“结果未知”测试通过。

### 阶段 B：接入单台机械臂

交付：驱动适配器、连接检查、移动、停止、安全高度/范围、校准、断连和错误分类。

验收：在低速和已确认安全范围内完成移动/停止/停靠；无限位设备拒绝自动回零与自动寻找
Z 限位，daemon `go_home` 只停止并保持当前位置。急停后不能自动恢复运动；
断连不会报告“已完成”；驱动错误有结构化类别和中文说明。

### 阶段 C：接入单个摄像头

交付：采集、曝光/分辨率配置、设备绑定、截图哈希、画面质量检查和证据索引。

验收：能稳定采集清晰画面；摄像头遮挡、断开、过曝和画面冻结均能识别；不能确认界面时状态为“无法确认”或“画面异常”。

### 阶段 D：实现微信适配器，但先不发送

交付：Fleet 按设备提供 `screen-observation.v1` 帧/OCR 证据和只读查看；
外部插件提供指定会话打开、页面核对、有限列表导航及动作证据；
由 WX 消费画面并完成一对一会话发现、身份、基线、消息和撤回处理。

验收：帧与设备、摄像头、绑定、daemon 会话一致；过期帧和无效校准被明确拒绝；
WX 重复消费不重复入库，低置信度或身份不明由 WX 转人工，不把同名直接合并。
群聊不属于当前主链路。旧 `capture_message` 仅供仿真，不能作为真机生产消息入口。

### 阶段 E：实现聊天发送闭环

交付：接收 `chat-send.v1` 和 `wx-session.v1`，完成目标账号/会话与正文哈希校验、
输入、发送取证、结果回报及对应收尾。自动发送复用匹配会话后退出；人工发送保持聊天，
另行退出或按手机已回主页的新证据只读释放。手动发送不依赖 DS/RAG 或草稿审批。

验收：成功返回“已发送”；明确未发送返回“明确失败”；点击或输入后断连返回“结果未知”；
三类结果都能回 WX 对账。人工发送不得自动退出，`wx_session_release` 不执行任何机械动作；
发送已确认但收尾失败保留发送事实且不重发。安全检查失败仍阻止新任务。

### 阶段 F：扩展十台设备

交付：设备发现、固定绑定、并行调度、单设备串行、健康检查、控制台、升级和回滚。

验收：十台同时运行不串账号、不串会话、不共享设备锁；Mac mini 重启后逐台核对驱动、
绑定、校准和遗留任务，不自动回零、不重放未知动作；全局急停后停止领取新任务。

### 阶段 G：插件开发者交接（平台不实现具体业务）

交付：插件 SDK/接口、插件清单格式、权限与资源范围校验、安装/卸载/升级/回滚机制、fake 设备和示例插件。拍照、录屏、桌面巡检、刷视频、简单 RPG 等具体能力由其他团队按插件规范独立开发，不属于 Arm Fleet 平台交付物。

验收：平台能审查每个插件的任务类型、能力、参数上限、权限、数据范围和证据声明；插件不能绕过运行时或抢占未声明资源。是否读取 WX、写入 WX 或操作特定应用，由插件与接入方的独立契约决定；平台只执行声明和授权边界。

## 五、机械臂驱动适配器必须实现的最小接口

具体方法名可按 SDK 改名，但语义不能改变：

```text
连接() -> 连接结果
断开() -> 断开结果
读取状态() -> 位置、限位、错误和急停状态
回到安全位置() -> 运动结果和证据
移动到预设位置(位置编号) -> 运动结果和证据
点击(目标位姿或已标定目标) -> 动作结果和证据
输入(文本或外部输入代理) -> 动作结果，不得修改文本
停止() -> 停止结果
急停() -> 急停结果
```

驱动层必须负责单位换算、速度/加速度上限、软限位、碰撞/过载错误、超时和断连；上层插件不得直接调用 SDK。

## 六、摄像头适配器必须实现的最小接口

```text
打开() -> 设备信息
关闭() -> 关闭结果
采集画面() -> 图像引用、采集时间、分辨率和哈希
检查画面质量() -> 清晰、遮挡、过曝、冻结或异常
提供屏幕证据() -> 设备/摄像头/绑定/会话信息、校正图、OCR 和哈希
```

通用摄像头适配器只提供原始观测和证据，不负责创建客户、识别消息业务含义或决定发送。
已登记页面/区域的证据能力供外部插件执行时核对账号、会话和应用页面，
不把微信主界面识别强加为通用摄像头驱动接口。

## 七、不能由独立 Agent 自行决定的事项

- 机械臂型号、SDK 和通信参数。
- 微信窗口布局、坐标、OCR 阈值和登录方式。
- 十台设备与账号的绑定关系。
- 外部插件允许操作哪些应用。
- 外部插件的动作白名单、次数上限、时长上限和数据范围。
- 急停后是否需要现场人员复位。
- 证据的原图保存位置、保留期限和访问人员。
- 任何“看起来像成功”但缺少结构化证据的结果。

这些信息缺失时，Agent 必须停在仿真或人工确认状态，不能用默认值直接控制真机。

## 八、交付给 WX 联调的最小包

独立 Agent 完成相应软件与契约阶段后，应交付：

1. `screen-observation.v1` 屏幕证据响应及 WX 消费夹具，包含设备、摄像头、绑定、daemon 会话、帧时间/序号、图像哈希和 OCR；校准无效返回 HTTP 409。`customer-message.v1` 属于 WX 入站语义及历史仿真兼容，不要求 Fleet 在真机主动生成。
2. `chat-send.v1`、`wx-session.v1` 和 `wx-list-navigation.v1` 示例，证明正文/哈希/设备/会话不可被篡改、旁观保留聊天、退出独立、无档案不滑动。
3. `task-result.v1` 的“已发送、明确失败、结果未知”三类结果示例。
4. fake 设备和录制画面测试夹具。
5. 设备绑定表、能力清单、版本清单和已知限制。
6. 故障注入报告：离线、错账号、错会话、摄像头异常、点击后断连、归位失败和急停。

WX 侧只根据契约接入，不读取机械臂品牌专属驱动、校准文件、机械坐标或手势坐标；
WX 会解释屏幕证据中的 OCR/图像，但不依赖 Fleet 内部 OCR 对象或引擎实现。

## 九、交付判定

软件联调与现场交付分开判断。可交给 WX 开始隔离软件联调的门槛是：

- 对应仿真和契约测试通过，包含屏幕证据消费、自动/人工会话和三类结果对账。
- 中文关键值在控制台、日志摘要、报告和任务说明中生效。
- 运行时没有把客户画像、价格事实和销售阶段放入 Arm Fleet。
- 文档、配置、契约示例、测试和已知限制随项目一起交付。

宣称现场交付还须另有单台安全动作、当前校准、页面/发送证据、故障注入，
以及十台真实绑定、并行、隔离、急停和重启恢复的记录。不得把前一层软件联调通过
写成后一层真机全部通过，也不得把尚无十台真机误写成软件无法联调。
