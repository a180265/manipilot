# 端到端流量测试载具重建计划（240 例跳过的恢复路径）

## 现状

测试套件中有 **240 例端到端流量用例**以"业务示例插件"为载具（注册任务类型 →
提交任务 → 驱动真实仿真链路 → 断言结果与证据）。抽取 SDK 时业务示例插件不在
发行范围，这些用例经 `needs_biz_example`（skipif）整批跳过——功能代码都在，
缺的是**驱动它们的载具**。

## 目标形态

新建 `examples/plugins/biz-example-adapter/`（中性示例业务插件），至少提供：

1. **manifest**：注册若干演示任务类型（如 `demo_conversation_open`、
   `demo_message_send`、`demo_list_scroll`），声明能力、权限、资源范围；
2. **plugin.py**：把任务翻译为平台通用动作（固定目标点击、校准直驱滑动、
   OCR 文字定位），不读取任何业务数据；
3. **固定目标约定**：`send_button`、`delete_key`、`conversation_item` 等目标键
   （与现有 ui_targets 体系对齐，动态目标带外部会话编号）；
4. **证据挂点**：动作前后帧与结果契约，供流量测试断言。

## 重建步骤

1. 以 `examples/plugins/gesture-validation-adapter` 为模板写最小骨架，
   先过 `test_gesture_plugins` 式的装载/契约测试；
2. 试点 3 个高价值文件：`test_stage_b_park.py`、
   `test_navigation_execution_gates.py`、`test_screen_gesture_integration.py`
   ——把任务请求从业务契约形状改为中性形状，去掉文件级 `pytestmark`；
3. 试点绿后按目录批量转换其余文件（请求形状机械改写为主）；
4. 全部恢复后移除 `needs_biz_example` skipif 机制与本计划文档。

## 工程量与顺序

多会话项目。建议顺序：骨架 → 试点三文件 → 校准/滑动族 → 导航/停车族 →
收尾清理。每步以全量套件绿为门槛。
